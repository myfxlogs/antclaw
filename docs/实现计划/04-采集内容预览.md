# 04. 采集内容预览（管理端查看每个数据源的真实数据）

> **同步（2026-04）**：汇总与预览已改为 **Connect `AdminDataService`**（`GetDataSummary` / `GetDataPreview`）；实现位于 `backend/internal/adapter/rpc/data_corpus.go` 与 `admin_data_connect_handler.go`。下文仍保留 JSON 形状说明，路径以 Connect 为准。

## 目标

管理员在管理端点进 "采集数据" 页时，不仅能看到每张表的**行数 + 最新时间**（`GetDataSummary`），还能**下钻查看最近 N 条原始行**（`GetDataPreview`），用于：

- 验证采集是否真的在写入有效数据（而不是写了一堆空值 / 错误字段）
- 肉眼检查字段是否对齐（例如 FRED `series_id`、`value`、`period` 是否合理）
- 出问题时快速定位是采集错还是分析错

## 背景（当前状态）

- `backend/internal/adapter/rpc/data_corpus.go` 维护采集表 → `(job_id, name, table, time_col)` 白名单映射
- 前端 `frontend/admin/src/pages/DataSummary.tsx` 通过 `lib/api.ts` 调用 Connect，可汇总并预览（`rows_json` 解析为表格行）

## 设计决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 展示形式 | 表格化动态列 | 不预先枚举字段，按 PostgreSQL `information_schema.columns` 返回 |
| 安全 | 仅白名单 `dataSourceTables` 中列出的表可预览 | 禁止任意 SQL 注入式访问 |
| 返回量 | 默认 50 行，可 `?limit=` 最多 200 | 避免大表 OOM |
| 排序 | 按 `time_col DESC`；`time_col` 为空时按 `id DESC` 兜底 | 优先让用户看到"最新" |
| 脱敏 | 无（采集数据本身是公开市场数据），但**bytea 等二进制列转 hex + 截断** | 避免前端崩溃 |
| 权限 | 复用 Admin JWT（Connect 拦截器注入 `Authorization`） | 统一 |

## 数据模型

无新表。

## 接口契约

### Connect RPC（当前）

| 服务 | RPC | 说明 |
| --- | --- | --- |
| `antclaw.v1.AdminDataService` | `GetDataSummary` | 汇总全部白名单表行数 + 最新时间 |
| `antclaw.v1.AdminDataService` | `GetDataPreview` | `job_id` + `limit`（1–200），预览行在响应 `rows_json`（JSON 数组字符串） |

### 响应结构

```json
{
  "job_id": "macro-sync",
  "table": "macro_indicators",
  "time_col": "period",
  "columns": ["series_id", "period", "value", "created_at"],
  "rows": [
    { "series_id": "DGS10", "period": "2026-04-26T00:00:00Z", "value": 4.23, "created_at": "2026-04-26T09:51:32Z" },
    ...
  ],
  "total_sampled": 50
}
```

- `columns` 保持 PostgreSQL 原始列顺序
- `rows` 是 `[]map[string]any`，由 `pgx.CollectRows` 转出
- `total_sampled` 是实际返回行数（≤ limit）

### 错误返回

```json
{ "error": "unknown job_id: foo" }     // 400
{ "error": "table not allowed" }       // 403（理论上不会触发，白名单兜底）
{ "error": "query timeout" }           // 504（设置 ctx.WithTimeout 5s）
```

## 关键流程

### Handler 伪代码

```go
func (h *DataPreviewHandler) Handle(w http.ResponseWriter, r *http.Request) {
    if _, err := requireAuth(r); err != nil { writeJSONError(w, 401, err); return }

    jobID := r.URL.Query().Get("job_id")
    mapping, ok := findMapping(jobID)                 // 从 dataSourceTables 查
    if !ok { writeJSONError(w, 400, fmt.Errorf("unknown job_id: %s", jobID)); return }

    limit := 50
    if v := r.URL.Query().Get("limit"); v != "" {
        if n, err := strconv.Atoi(v); err == nil && n > 0 && n <= 200 { limit = n }
    }

    ctx, cancel := context.WithTimeout(r.Context(), 5*time.Second)
    defer cancel()

    orderBy := quoteIdent(mapping.TimeCol)
    if mapping.TimeCol == "" { orderBy = "id" }

    sql := fmt.Sprintf(`SELECT * FROM %s ORDER BY %s DESC NULLS LAST LIMIT $1`,
                       quoteIdent(mapping.Table), orderBy)

    rows, err := h.pool.Query(ctx, sql, limit)
    if err != nil { writeJSONError(w, 500, err); return }
    defer rows.Close()

    columns := fieldNames(rows.FieldDescriptions())
    items, err := pgx.CollectRows(rows, pgx.RowToMap)
    if err != nil { writeJSONError(w, 500, err); return }

    // 规范化：bytea → hex + 截断；time.Time → RFC3339
    for _, row := range items { normalizeRow(row) }

    writeJSON(w, 200, map[string]any{
        "job_id": jobID, "table": mapping.Table, "time_col": mapping.TimeCol,
        "columns": columns, "rows": items, "total_sampled": len(items),
    })
}
```

### `normalizeRow` 必须处理

- `[]byte` → `"0x"+hex.EncodeToString(v[:min(64,len)])` + 如果截断加 `...`
- `time.Time` → `.Format(time.RFC3339Nano)`
- `pgtype.Numeric` → 转 string（避免 float 精度丢失）
- `nil` 保留 `null`，前端能渲染空单元

### 白名单查找

```go
func findMapping(jobID string) (tableMapping, bool) {
    for _, m := range dataSourceTables {
        if m.JobID == jobID { return m, true }
    }
    return tableMapping{}, false
}
```

> 白名单表映射仅维护 **`data_corpus.go` 一份**，不要复制。

## 前端 UX 建议

### DataSummary 行内新增按钮

```
| 数据源 | 行数 | 最新时间 | 状态 | [查看]  |
```

点击 `查看` → 打开 `<DataPreviewModal jobId=... />`

### DataPreviewModal

- 顶部：数据源名 + 表名 + "显示最近 [20|50|100|200] 条" 选择器
- 主体：`<table>` 动态列
- 列渲染规则：
  - 时间列（与 `time_col` 同名）高亮 + 格式化本地时间
  - 数值列右对齐
  - `null` 渲染为灰色 `—`
  - 超长字符串（>80 字符）鼠标悬停展开
- 底部：关闭 + "复制 JSON" 按钮（方便贴到工单）

### 边界测试

1. 未知 `job_id=foo` → 400
2. `limit=99999` → 自动钳制到 200
3. 空表（刚清库）→ `rows: []`, `total_sampled: 0`
4. 包含 `bytea` 的表（如果有）→ hex 字符串，不崩
5. 未登录 → 401

## 注意事项

- **SQL 注入防御**：`quoteIdent(table)` 与 `quoteIdent(timeCol)` 必须走白名单，不接收用户输入
- **大表性能**：`time_col` 必须有索引（目前采集表都按时间索引，OK）
- **超时**：5s 兜底；若某表确实没时间索引（理论上不会），降级为 `id DESC`
- **跨列类型差异**：前端一定不能做 `parseInt` 兜底，保持 any 原样展示
- **审计**：本接口是读，暂不写审计；若未来加"导出 CSV" 需要补审计

## 风险与回退

- 风险：某字段值极大（JSON blob）导致前端渲染卡顿 → 后端截断字符串列到 1KB
- 回退：直接移除路由注册，前端禁用"查看"按钮；无需 DB 迁移
