# 05. 回测策略管理（CRUD + 启停 + 执行 mock）

## 目标

在管理端提供一个"交易策略"管理面板，能：

- **新增 / 编辑 / 删除 / 启停** 策略（全生命周期管理）
- **运行一次**（先返回 mock 回测结果，后续再接真实引擎）
- 查看每个策略的 **历史运行** 与 **当前状态**

本期聚焦"**接口先做完整、执行先 mock**"，保证前端 UX 闭环；真实回测引擎的接入放后续。

## 背景

- 项目已有 `backtest_jobs` / `backtest_results` 表（用于真实回测）
- 但**没有"策略定义"本身的管理结构**——当前策略是代码/常量级
- 管理员希望：加一个策略（比如 "均线交叉 EUR/USD 1H"），一键启用，系统定期自动跑，结果可看

## 设计决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 执行引擎 | 本期 mock（1-2s 延迟 + 随机指标），保留真实引擎接口 | 不阻塞前端，按计划走 |
| 策略参数 | `params JSONB` 柔性字段 | 不同策略参数不同，严格 schema 会过早锁死 |
| 启停 | `enabled BOOLEAN` | 与 `status` 分离；status 表示 draft / active / archived |
| 删除策略 | 软删（`deleted_at`） | 已产生的回测记录不能孤儿；硬删通过 SQL 手动 |
| 调度 | 启用的策略由 worker 按 `schedule_cron` 定时触发（本期可先支持 `@hourly` / `@daily` 预设字符串） | 复用 worker 已有定时循环 |
| 接口签名 | 写操作都走 HMAC 签名 + nonce（同数据源） | 统一安全模型 |
| 参数验证 | 后端 service 层 | handler 仅 JSON 解析与 auth |
| 权限 | admin only | 与数据源页一致 |

## 数据模型

### 新表：`strategies`

```sql
CREATE TABLE IF NOT EXISTS strategies (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name            TEXT NOT NULL,
    kind            TEXT NOT NULL,          -- 策略类型标识：ma_cross / rsi_reversal / cot_extreme / ...
    symbol          TEXT NOT NULL,          -- 标的：EURUSD / BTCUSDT / SPX / ...
    timeframe       TEXT NOT NULL,          -- 1h / 4h / 1d
    params          JSONB NOT NULL DEFAULT '{}'::jsonb,
    schedule_cron   TEXT NOT NULL DEFAULT '@hourly',  -- @hourly / @daily / 0 */4 * * *
    enabled         BOOLEAN NOT NULL DEFAULT FALSE,
    status          TEXT NOT NULL DEFAULT 'draft',    -- draft / active / archived
    description     TEXT NOT NULL DEFAULT '',
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    created_by      TEXT NOT NULL DEFAULT '',
    updated_by      TEXT NOT NULL DEFAULT '',
    last_run_at     TIMESTAMPTZ,
    last_run_status TEXT,                   -- success / failed / running
    deleted_at      TIMESTAMPTZ
);

CREATE INDEX IF NOT EXISTS idx_strategies_enabled ON strategies(enabled) WHERE deleted_at IS NULL;
CREATE INDEX IF NOT EXISTS idx_strategies_kind ON strategies(kind) WHERE deleted_at IS NULL;
```

### 定时调度（worker）

```go
// worker main loop 里新增一个 ticker（1 分钟粒度）
strategyTicker := time.NewTicker(1 * time.Minute)

for {
    select {
    case <-strategyTicker.C:
        runDueStrategies(ctx, dbpool, strategySvc, logger)
    ...
    }
}

func runDueStrategies(ctx, pool, svc, logger) {
    rows := pool.Query(`SELECT id, schedule_cron, last_run_at FROM strategies
                        WHERE enabled=TRUE AND deleted_at IS NULL`)
    for each row:
        if isDue(schedule_cron, last_run_at):
            runWithEvent(ctx, logger, "strategy-"+id, name, func() error {
                _, err := svc.Run(ctx, id, triggeredBy="scheduler")
                return err
            })
}
```

`isDue` 支持预设字符串：

```go
switch cron {
case "@hourly":  due = now.Sub(lastRun) >= time.Hour
case "@daily":   due = now.Sub(lastRun) >= 24*time.Hour
case "@weekly":  due = now.Sub(lastRun) >= 7*24*time.Hour
default:         // 真实 cron 表达式 → 使用 github.com/robfig/cron/v3 解析
}
```

真实 cron 解析可放第二期；本期支持 3 个预设足够。

## 前端 UX 建议

### 列表页 `/strategies`

- 顶部：搜索框（按 name / symbol / kind）+ 过滤（状态 / 启停 / 定时）
- 表格列：名称 / 标的 / 周期 / 定时 / 启停开关 / 最后运行 / 操作
- 操作：查看、编辑、运行（确认框：模拟 or 真实）、删除（软删二次确认）

### 编辑页 `/strategies/new` 与 `/strategies/:id`

- 基本信息（name / symbol / timeframe / kind 下拉）
- `params` 用 Monaco JSON 编辑器；给每个 kind 预填默认模板
- `schedule_cron` 单选（预设 3 个）或自由输入 cron 表达式（二期支持）
- 底部：保存（hybrid + sign）/ 取消

### 运行历史页 `/strategies/:id`

- 展示该策略的 `backtest_results` 最近 50 条
- 列：开始时间 / 状态 / total_return / sharpe / max_dd / mock? / 详情
- 支持按日期范围过滤、按 metric 排序

## 注意事项

- **cron 解析**：本期仅支持 3 个预设串；自由 cron 必须用成熟库（robfig/cron），**绝不自研**
- **并发**：同一 strategy 同时只能有一个 running run；worker 侧加 Redis `SETNX strategy:running:<id>` 做互斥锁，TTL 30 分钟兜底
- **失败隔离**：任何一个 strategy 的 Run 失败不能影响其他；`runWithEvent` 已有 recover
- **mock 必须可见**：接口响应 + 前端 UI 都要明确标识，避免运维误以为真实回测
- **软删恢复**：管理员可能误删；提供 `DELETE ... WHERE id=?` 撤销脚本，或加 `POST /admin/strategies/{id}/restore`（非本期）
- **审计 details 不含 params 值**：避免未来如果 params 出现敏感字段（如 API key）泄露到审计表

## 风险与回退

- 风险：调度 tick 与业务 tick 互相影响 → 各 ticker 在独立 goroutine，panic recover 隔离
- 风险：strategies 表积累无用草稿 → 定期清理 draft + 无 run 的策略（>90 天）；本期不做
- 回退：前端禁用新增按钮，后端路由保留只读；已建的 strategies 表无损
