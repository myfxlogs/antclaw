## 2. 单元测试（Unit）

### 2.1 覆盖率门槛

| 包类型 | 目标 |
|---|---|
| `service/<capability>/` 业务核心 | ≥ 80% |
| `infra/apiclient/<vendor>/` 适配器 | ≥ 70% |
| `adapter/rpc/*_handler.go` | ≥ 60% |
| `cmd/...` 入口 | 不强制（只跑 build） |

工具：`go test -race -cover ./...`

### 2.2 命名

```go
func TestGEX_Calculate_BasicCase(t *testing.T) { ... }
func TestGEX_Calculate_EmptyOptions_ReturnsZero(t *testing.T) { ... }
func TestDeribit_GetBookSummary_RetriesOn500(t *testing.T) { ... }
```

### 2.3 必须包含的测试类型

- **Happy Path**：输入正确、输出正确
- **Edge Case**：空输入、极值、单元素
- **Error Path**：依赖错误、解析错误、超时
- **回归**：拷贝 ARK `*_test.go` 中的全部用例（语义等价）

### 2.4 子测试 / Table-Driven

复杂分支必须 table-driven：

```go
cases := []struct{
    name     string
    input    Input
    want     Output
    wantErr  string
}{
    {"normal", inputA, outA, ""},
    {"empty",  Input{}, Output{}, "empty input"},
}
for _, tc := range cases {
    t.Run(tc.name, func(t *testing.T) { ... })
}
```

## 3. 集成测试（Integration）

### 3.1 范围

- service ↔ apiclient（mock vendor 的 httptest.Server）
- service ↔ Postgres（用 `testcontainers-go` 拉一个临时 PG）
- service ↔ Redis（用 miniredis 或 testcontainers）

### 3.2 文件命名

`*_integration_test.go`，加 `//go:build integration` tag，避免 `go test ./...` 默认拉起。

```go
//go:build integration

package onchain

func TestOnchain_E2E_FromCoinmetricsToDB(t *testing.T) { ... }
```

CI 通过 `go test -tags=integration ./...` 单独跑。

### 5.3 文件长度检查

`scripts/lint-filesize.sh`（新建，仓库根目录执行）：

```bash
#!/usr/bin/env bash
# 800 行硬上限检查：仅 Markdown 文档例外。
# 覆盖范围：Go 源码（含测试）、Proto 定义、Proto 生成产物、前端 TS/TSX/Vue、Shell、Python、SQL 迁移。
set -euo pipefail
THRESHOLD=800

# 受检扩展名（不含点）
EXTS=(go proto pb.go connect.go _pb.ts _connect.ts ts tsx vue sh py sql)

# 受检目录
DIRS=(backend frontend proto gen scripts deploy)

FILES=$(
  for d in "${DIRS[@]}"; do
    [ -d "$d" ] || continue
    find "$d" -type f \
      \( -name "*.go" -o -name "*.proto" \
         -o -name "*.ts" -o -name "*.tsx" -o -name "*.vue" \
         -o -name "*.sh" -o -name "*.py" -o -name "*.sql" \) \
      ! -path "*/node_modules/*" ! -path "*/dist/*" ! -path "*/build/*"
  done
)

VIOLATIONS=$(
  echo "$FILES" | xargs -r wc -l 2>/dev/null \
    | awk -v t=$THRESHOLD '$1 > t && $2 != "total" {print $0}'
)

if [ -n "$VIOLATIONS" ]; then
  echo "ERROR: 以下文件超过 $THRESHOLD 行，需要拆分（仅 Markdown 文档例外）："
  echo "$VIOLATIONS"
  echo
  echo "提示："
  echo "- Proto 定义过大：按能力拆为多个 Service / 多个 .proto 文件"
  echo "- Proto 生成产物（*.pb.go / *.connect.go）过大：拆分上游 proto，不要手改生成文件"
  echo "- Go 源码过大：按子领域 / 按算法 / 按端点拆分"
  exit 1
fi
echo "OK: 所有受检文件 ≤ $THRESHOLD 行"
```

**仅 Markdown 文档（`*.md`）例外**。`*_test.go`、`*.proto`、`*.pb.go`、`*.connect.go` 均参与检查。

## 6. 静态分析

### 6.1 后端

```bash
go vet ./...
gofmt -d -s .                  # 必须无差异
goimports -l -d .              # 必须无差异
golangci-lint run              # 配置见 .golangci.yml
```

`.golangci.yml` 关键 linter：

```yaml
linters:
  enable:
    - errcheck
    - govet
    - staticcheck
    - gosimple
    - ineffassign
    - unused
    - misspell
    - nilerr
    - exhaustive
    - bodyclose
    - sqlclosecheck
issues:
  exclude-rules:
    - path: _test\.go
      linters: [errcheck, unused]
```

### 6.2 前端

```bash
cd frontend/admin
npm run lint
npm run typecheck     # tsc --noEmit
```

## 7. CI 流水线节点（顺序）

```yaml
jobs:
  ci:
    steps:
      - checkout
      - setup-go
      - setup-node
      - run: bash backend/scripts/lint-protocol.sh
      - run: bash backend/scripts/lint-filesize.sh
      - run: gofmt -d -s . && goimports -l -d .
      - run: go vet ./...
      - run: golangci-lint run
      - run: go -C backend build ./...
      - run: go -C backend test -race -cover ./...
      - run: cd frontend/admin && npm ci && npm run lint && npm run typecheck && npm run build
      - run: cd frontend/web   && npm ci && npm run lint && npm run typecheck && npm run build
      - run: bash scripts/e2e/run-all.sh   # 仅在发布候选分支跑
```

## 9. 代码评审清单

评审者必须逐条核对：

- [ ] 是否引入新的 REST/WS/fetch（除白名单）
- [ ] 是否有任何非 Markdown 文件 > 800 行（Go 源码、proto、生成产物、TS/Vue、Shell、SQL 均计）
- [ ] 是否有任何 vendor 包内做了业务派生
- [ ] 是否有 service 包内直接发起 HTTP（应通过 apiclient）
- [ ] 错误是否用 `fmt.Errorf("...: %w", err)` 包装
- [ ] 是否使用 `slog` 结构化日志
- [ ] 是否有 N+1 查询、未关闭的 rows、未 defer 的 cancel
- [ ] 测试覆盖率是否达标
