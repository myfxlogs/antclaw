## 3. 关键算法（教科书简化版）

### 3.1 Wyckoff 分类
基于过去 10 日窗口与 ATR(14)：

- `SPRING`：`low < prevLo + 0.05·atr` 且 `close > prevLo` —— 假突破回收（看多）
- `UPTHRUST`：`high > prevHi - 0.05·atr` 且 `close < prevHi` —— 假突破回落（看空）
- `SOS`：`close > MA(10)` 且 `close-open > 0.3·atr` —— 强势上行
- `SOW`：`close < MA(10)` 且 `open-close > 0.3·atr` —— 强势下行

`confidence = min(1, |close-MA| / (2·atr))`。

### 3.2 GEX（Gamma Exposure）
对 Deribit 期权链：

```
gamma_i  ≈ exp(-d1²/2) / (S · σ · √T · √(2π))
GEX_call =  gamma · OI · S² · 0.01
GEX_put  = -gamma · OI · S² · 0.01
```

按 strike 聚合：`total_gex = Σ net_gex`，`flip_level` 取 ±20% 范围内最接近零的 strike，`max_call_wall / max_put_wall` 取最大正/负净 gamma。

### 3.3 IV Skew
- 5-point smile：moneyness ∈ {0.90, 0.95, 1.00, 1.05, 1.10}，按最近到期日匹配。
- `skew_slope = (IV_0.9 - IV_1.1) / 0.2`
- `term_slope = (IV_late - IV_early) / (T_late - T_early)`
- `pc_iv_ratio = (Σ put IV·OI / Σ put OI) / (Σ call IV·OI / Σ call OI)`

### 3.4 Walk-forward
固定 180 天训练 + 30 天测试，滚动 30 天步长；策略为 `MA(20)/MA(50)` 顺势/反向二选一开关，OOS 阶段使用训练期更优方向并计算年化 Sharpe。

### 3.5 Micro 代理
缺乏真实订单簿时，从 5m K 线派生：
- `obi_top10 = 2·(close-low)/(high-low) - 1`，∈ [-1, 1]
- `spread_bps = (high-low)/close · 10000`
- `bid/ask_depth = volume · (1 ∓ pos)`
- `stress_score = |obi| + spread_bps/100`

### 3.6 Regime 历史回填
仅在 `regime_transitions` 为空时执行一次：以 `(close - MA50)/ATR14` 为强度因子 s，按 ±0.5 / ±1.5 阈值映射 5 档 label，沿 `price_daily` 滚动写入历史；相邻日 label 变化时写入 transition。`available_models` 标记为 `["heuristic"]`，与生产 Compute 写入的多模型记录区分。

## 4. 已知工程修正

1. **`event_impact_records.window` 列名是 SQL 保留字**，必须用 `"window"` 双引号写入。
2. **`INSERT … SELECT … WHERE NOT EXISTS` 同参数复用** 触发 PG `42P08 inconsistent types deduced`，修复方式是显式 `$1::varchar` 等类型转换。
3. **`regime_overlay_history.available_models` 列为 jsonb**，原代码以 `strings.Join(",")` 写 TEXT 触发 `invalid input syntax for type json`，修正为 `json.Marshal` 数组。
4. **`buildTransitionMatrix` 之前查询 `timeframe='1d'`**，但 regime 服务写入 `'D'`，导致始终匹配为 0；统一为大写 `'D'`。
5. **`price_daily` 同日多源去重**：Wyckoff loadDailyBars 改为 `GROUP BY time::date`（开盘取最早、收盘取最晚、high/low 取极值）。
6. **`calendar_events.scheduled_at` 当前为 `0001-01-01`**（calendar-sync 解析 bug 待修），`calendar-surprise`/`event-impact` 临时回退到 `fetched_at`，避免完全没有候选数据。
