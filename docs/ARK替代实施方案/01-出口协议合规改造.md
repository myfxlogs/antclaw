# 01 · 出口协议合规改造

> 本文给出消除 REST/WS/轮询的精确改造步骤，作为 M1 的前置条件。
> 完成后，仓库内不应再出现任何对外 REST 端点或前端 `fetch/axios/WS/setInterval`。

---

## 1. 现状审计结果

| 编号 | 路径 | 现状 | 违规原因 |
|---|---|---|---|
| C-1 | `backend/cmd/antclaw-api/main.go` 中 `mux.HandleFunc("/health", ...)` | REST GET | 出口暴露 REST |
| C-2 | `backend/cmd/antclaw-api/main.go` 中 `mux.HandleFunc("/", ...)` | REST GET | 出口暴露 REST |
| C-3 | `frontend/admin/src/lib/api.ts` 中 `fetch('${API_BASE_URL}/health')` | REST 调用 | 前端使用 fetch |
| C-4 | `frontend/admin/src/lib/crypto.ts` 中 `fetch(url, ...)` 投递 envelope | REST POST | 前端使用 fetch |

合规项（保持不变）：
- 全部 `/antclaw.v1.*` Connect handler
- `/sse/jobs`、`/sse/audit` SSE handler

## 2. C-1 / C-2：删除根路径与健康检查 REST

### 2.1 后端改造

**文件**：`backend/cmd/antclaw-api/main.go`

**改造步骤**：

1. 删除 `mux.HandleFunc("/health", ...)` 与 `mux.HandleFunc("/", ...)` 两段。
2. 在 proto 中新增 `SystemService.Healthz`（详见 `03-Proto契约新增清单.md` §SystemService）。
3. 在 `internal/service/system/` 新建 `service.go`，提供 `Healthz` 方法：检查 Postgres、Redis、关键 Job 心跳。
4. 在 `internal/adapter/rpc/system_handler.go` 实现 Connect handler。
5. 在 `cmd/antclaw-api/main.go` 注册：
   ```go
   mux.Handle(antclawv1connect.NewSystemServiceHandler(systemHandler))
   ```

### 2.2 容器健康探针迁移

**文件**：`deploy/docker-compose.yaml` 中 `api` service 的 `healthcheck`

```yaml
healthcheck:
  test:
    - CMD-SHELL
    - 'wget -q -O /dev/null --header="Content-Type: application/json" --post-data="{}" http://localhost:8080/antclaw.v1.SystemService/Healthz || exit 1'
  interval: 15s
  timeout: 5s
  retries: 5
```

> 不要使用 `grpc_health_probe`，原因：Connect 走 HTTP/1.1 + JSON 时 grpc-health 协议不通用；用 `wget POST` 最稳定。

### 2.3 前端调用迁移

**文件**：`frontend/admin/src/lib/api.ts`

将健康检查替换为：

```ts
// 原：const resp = await fetch(`${API_BASE_URL}/health`)
const systemClient = createClient(SystemService, transport)
const resp = await systemClient.healthz({})
```

`SystemService` 由 `buf generate` 后的 `gen/ts/antclaw/v1/system_pb.ts` 提供。

## 3. C-4：crypto.ts envelope 改走 Connect

### 3.1 现状分析

`frontend/admin/src/lib/crypto.ts` 用 `fetch()` POST 一个加密 envelope；后端有对应解码 + 路由的端点（属于自定义 REST 行为）。这违反"出口仅 Connect/SSE"原则。

### 3.2 改造方案

**Proto 新增**（详见 `03-Proto契约新增清单.md` §CryptoService）：

```proto
service CryptoService {
  rpc GetCryptoPublicKey(GetCryptoPublicKeyRequest) returns (GetCryptoPublicKeyResponse);
  rpc PostEnvelope(PostEnvelopeRequest) returns (PostEnvelopeResponse);  // 新增
}

message PostEnvelopeRequest {
  string body_b64 = 1;        // RSA+AES 加密后的 envelope JSON（base64）
  string ts = 2;
  string nonce = 3;
  string sig = 4;             // HMAC-SHA256
  string target_path = 5;     // 原 REST 路径，例如 "antclaw.v1.UserService/UpdateSettings"
  string target_body_b64 = 6; // 解密后的内层 JSON RPC body（base64）
}

message PostEnvelopeResponse {
  string body_b64 = 1;        // 加密后的内层 RPC 响应
}
```

### 3.3 后端实现

**文件**：`backend/internal/adapter/rpc/crypto_handler.go`（扩展）

`PostEnvelope` 实现伪码：

```go
func (h *CryptoHandler) PostEnvelope(ctx context.Context, req *connect.Request[v1.PostEnvelopeRequest]) (*connect.Response[v1.PostEnvelopeResponse], error) {
    // 1. 解密 body_b64 -> innerBody
    // 2. 校验 sig（HMAC-SHA256(sessionKey, ts\nnonce\nbody)）
    // 3. 构造一个内部 connect.Request，调度到 target_path 对应 Service
    // 4. 拿到 response.Marshal()，加密为 enc
    // 5. 返回 enc
}
```

> 关键约束：内层调度必须**通过 in-process Service 接口直接调用**（不重新走 HTTP），避免回环。可在 `cmd/antclaw-api/main.go` 启动时把所有 Service 实例注入到 CryptoHandler。

### 3.4 前端改造

**文件**：`frontend/admin/src/lib/crypto.ts`

把 `fetch(url, {method:'POST', body: envelope, ...})` 改为：

```ts
const cryptoClient = createClient(CryptoService, transport)
const resp = await cryptoClient.postEnvelope({
  bodyB64: env.body,
  ts: env.ts,
  nonce: env.nonce,
  sig: env.sig,
  targetPath,
  targetBodyB64: innerBodyB64,
})
return decryptResponse(resp.bodyB64)
```

### 3.5 灰度切换计划

1. **第 1 步**：上线 `PostEnvelope` RPC，与现有 REST envelope 端点并存。
2. **第 2 步**：前端切到 RPC 调用，灰度 100%。
3. **第 3 步**：后端删除 REST envelope 端点；删除 `frontend/admin/src/lib/crypto.ts` 中所有 `fetch`。
4. **第 4 步**：CI 加固：`grep -rE "fetch\(|new WebSocket|setInterval" frontend/admin/src` 命中即失败（白名单见 §6）。

## 4. CI 加固：固化禁止 REST/WS/轮询

### 4.1 后端

**文件**：`backend/scripts/lint-protocol.sh`（新建）

```bash
#!/usr/bin/env bash
set -euo pipefail

VIOLATIONS=$(grep -rnE 'mux\.HandleFunc\(' backend/cmd backend/internal \
  | grep -vE 'jobsEventsHandler|auditEventsHandler|sse_handlers' || true)

if [ -n "$VIOLATIONS" ]; then
  echo "ERROR: 禁止新增 REST handler，仅允许 Connect / SSE。违规："
  echo "$VIOLATIONS"
  exit 1
fi

WS=$(grep -rnE 'gorilla/websocket|nhooyr.io/websocket' backend || true)
if [ -n "$WS" ]; then
  echo "ERROR: 禁止 WebSocket。违规："
  echo "$WS"
  exit 1
fi

echo "OK: 后端协议合规"
```

### 4.2 前端 ESLint 规则

**文件**：`frontend/admin/eslint.config.js`（追加规则）

```js
{
  rules: {
    'no-restricted-globals': ['error',
      { name: 'fetch', message: '禁止 fetch；统一用 connect-web' },
      { name: 'XMLHttpRequest', message: '禁止 XHR；统一用 connect-web' },
      { name: 'WebSocket', message: '禁止 WebSocket；统一用 SSE 或 Connect' },
    ],
    'no-restricted-syntax': ['error',
      { selector: 'CallExpression[callee.name="setInterval"]',
        message: '禁止 setInterval 用作业务轮询；UI 反馈用 setTimeout 一次性' },
      { selector: 'NewExpression[callee.name="WebSocket"]',
        message: '禁止 WebSocket' },
      { selector: 'CallExpression[callee.object.name="axios"]',
        message: '禁止 axios；统一用 connect-web' },
    ],
  },
}
```

### 4.3 CI 流水线节点

在 `.github/workflows/ci.yml` 或本地 `Makefile` 增加：

```makefile
lint-protocol:
	bash backend/scripts/lint-protocol.sh
	cd frontend/admin && npm run lint
	cd frontend/web   && npm run lint
```

并在 `make all` 中纳入 `lint-protocol`。

## 5. 例外白名单

以下使用允许保留（不会被 lint 拦截）：

| 场景 | 形式 | 原因 |
|---|---|---|
| connect-web 内部 | `transport.fetch` | 框架内部，非业务调用 |
| 浏览器加载静态资源 | `<img src>`、CSS `url()` | 非业务请求 |
| `setTimeout(fn, ms)` 用于 toast 自动消失、UI 节流 | 单次回调 | 非轮询 |
| `EventSource` | SSE 标准 | 已是合规协议 |
| 后端 `apiclient/<vendor>/` 内部 HTTP 调用 | 入口（第三方 API） | 不属于"出口" |
