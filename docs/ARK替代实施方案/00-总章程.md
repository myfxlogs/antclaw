# 00 · 总章程：AntClaw 100% 替代 ARK Intelligent

> 本目录是「100% 替代 ARK Intelligent」的施工蓝图。任一 AI 助手或工程师按本目录文档施工，应能不产生歧义地完成全部代码改造。
> 上游需求文档：`docs/AntClaw对ARK替代-差距清单.md`。
> 本目录不重复差距列表本身，只规定**怎么改、改到哪、验收什么**。

---

## 1. 项目目标（不可妥协）

1. **业务能力零回退**：ARK 现有的全部命令/分析/回测/告警，AntClaw 都必须有等价 Connect-RPC + 前端模块替代。
2. **出口协议唯一**：对外只暴露 **Connect-RPC / gRPC / SSE**。**禁止** REST、WebSocket、HTTP polling、SSE 之外的长连接。
3. **入口可宽松**：第三方 API 抓取使用 REST/HTTP 是允许的，但仅限 `internal/infra/apiclient/<vendor>/` 内部使用。
4. **数据源治理**：所有 vendor 通过 `internal/infra/apiclient/<vendor>/` 薄 client 接入，业务派生指标住对应 `internal/service/<capability>/`。
5. **可观测性**：所有 Job 必须发 SSE 状态；所有 vendor 必须有健康度指标；所有失败必须有可读 `last_error`。

---

## 2. 不可妥协的硬约束

### 2.1 代码硬约束

- **800 行上限**：任一代码/脚本文件 > **800 行** 必须拆分；**仅 Markdown 文档例外**。此规则同时适用于：
  - Go 源码（`*.go`，含 `*_test.go`）
  - Proto 定义（`*.proto`）：Service 过大时按能力拆为多个 proto 文件
  - Proto 生成代码（`*.pb.go`、`*.connect.go`、`*_pb.ts`、`*_connect.ts`）：若生成产物超标，必须通过拆分上游 proto 来消除
  - Shell / Python / TS / Vue 等任意脚本与源码
  - 数据库迁移 SQL（`*.sql`）：过大时按表或领域拆分
- 一切对外 HTTP 入口由 Connect handler 或 SSE handler 注册；**禁止** 新增 `mux.HandleFunc` 自定义 REST。
- 所有跨服务调用走 Connect-RPC；后端内部调用走 Go 函数；**禁止** 新增 HTTP 内部反向代理。
- 所有日志走 `slog`，结构化字段；错误用 `fmt.Errorf("...: %w", err)` 包裹。
- 所有外呼必须经过 `apiclient.Source` 中间件（限流/重试/断路器/超时/指标）。

### 2.2 前端硬约束

- 所有 RPC 调用走 `@connectrpc/connect-web`；所有事件流走 `EventSource`。
- **禁止** `fetch()` / `axios` / `XMLHttpRequest` / `new WebSocket` / `setInterval(轮询业务)`。
- `setTimeout` 仅允许用于 UI 反馈（如 toast 自动消失），不得用于业务轮询。
- ESLint/CI 必须固化以上约束（见 `11-测试与代码质量规范.md`）。

### 2.3 文档硬约束

- 所有交付文档以中文命名，存放 `docs/` 或 `docs/ARK替代实施方案/`。
- 每个里程碑结束后必须更新 `docs/AntClaw对ARK替代-差距清单.md` 的状态列。
- 每次合并 PR 必须附测试结果摘要 + 编译通过证明。

## 3. 目录与命名规范

```
backend/
├── cmd/
│   ├── antclaw-api/                  # Connect handler 注册中枢
│   └── antclaw-worker/               # Job 调度与采集
├── internal/
│   ├── adapter/
│   │   ├── rpc/                      # Connect handler 实现
│   │   └── sse/                      # SSE handler
│   ├── infra/
│   │   ├── apiclient/                # 通用 HTTP 中间件 + Source 接口
│   │   └── apiclient/<vendor>/       # ★ 每家数据源一个薄 client 子包
│   └── service/
│       └── <capability>/             # ★ 业务能力服务（onchain/options/defi/...）
proto/antclaw/v1/
└── <service>.proto                    # 每个 Service 一个 proto 文件
frontend/
├── admin/src/features/<module>/       # 管理端模块
└── web/src/features/<module>/         # 用户端模块
docs/
├── ARK替代实施方案/                   # 本目录
└── AntClaw-*.md                       # 既有文档
```

### 3.1 命名规则

| 对象 | 规则 | 示例 |
|---|---|---|
| Go 包路径 | 全小写、单词、无下划线 | `apiclient/deribit` |
| Go 文件 | 全小写、可下划线 | `iv_surface.go` |
| Proto Service | `PascalCase + Service` | `OnchainService` |
| Proto Method | `Verb + Noun` | `GetIVSurface` |
| Proto 文件 | `service.proto`（小写） | `onchain.proto` |
| SSE 通道 | `kebab-case` | `signals.regime` → `signals_regime` |
| 前端模块 | `features/<kebab-case>` | `features/options-gex` |
| Job ID | `kebab-case` | `walkforward-bt` |
| Redis Key | `colon:separated` | `jobs:status:<id>` |

## 4. 术语表（统一口径）

| 术语 | 定义 |
|---|---|
| **薄 client** | `infra/apiclient/<vendor>/` 下的协议层，仅做请求/解析/错误码，不做业务派生 |
| **业务能力服务** | `service/<capability>/` 下的领域服务，可调用多个薄 client，承载所有派生指标 |
| **Source 接口** | `apiclient.Source`，所有薄 client 实现的统一中间件入口 |
| **Job** | Worker 中可调度/手动触发/启停的最小执行单元，由 jobID 唯一标识 |
| **降级链** | 同一能力的多源回退顺序，存储于 `data_sources` 表 priority 字段 |
| **零回退** | ARK 现有任何能力在 AntClaw 中存在等价 RPC + 前端模块 |
| **入口** | 从第三方 API 抓数据的 HTTP 调用 |
| **出口** | AntClaw 对外暴露的接口 |

## 6. 施工流程（每个能力都按此走）

```
1. 读 differential gap：在差距清单中确认状态与 Proto 期望
2. 读对应里程碑文档：拿到目录、接口、字段、错误码
3. 写 proto：新增/扩展 *.proto，buf generate
4. 写薄 client（如需）：infra/apiclient/<vendor>/，纳入 Source 接口
5. 写业务服务：service/<capability>/，单元测试 ≥80%
6. 写 Connect handler：adapter/rpc/<service>_handler.go，注册到 cmd/antclaw-api
7. 写 Worker Job（如需）：cmd/antclaw-worker/collector_*.go + 加入 jobRunners
8. 写前端模块：features/<module>/，仅 connect-web + EventSource
9. 写中文文档：docs/<能力名>-说明.md
10. 跑：go build ./... && go test -race ./... && cd frontend/admin && npm run build
11. 改 docs/AntClaw对ARK替代-差距清单.md 状态列为 ✅
12. 提交 PR，附测试结果与编译证明
```

## 7. 完成判据（DoD - Definition of Done）

任一能力在以下条件**全部满足**时方可标记 ✅：

- [ ] proto 已生成 Go/TS 桩
- [ ] 后端服务实现完成；单元测试覆盖率 ≥ 80%（核心逻辑）/ ≥ 60%（适配器）
- [ ] Connect handler 已注册并通过 `curl -X POST /antclaw.v1.<Service>/<Method>` 端到端验证
- [ ] Worker Job（如有）已加入 `jobRunners`、`runAllCollections`、SSE 事件可见
- [ ] 前端模块可访问，错误状态友好显示，**无 fetch/axios/WS/setInterval**
- [ ] vendor（如有）薄 client 在 `data_sources` 表中有 seed，密钥可在 `/datasources` 热配
- [ ] 中文文档存于 `docs/`
- [ ] 差距清单状态更新为 ✅
- [ ] 容器重新构建并启动成功（`docker compose up -d --build api worker admin`）

## 8. 风险声明

- **第三方 API 不稳定**：BIS/SNB/DTCC/Eurostat 速率受限，需要本地缓存与失败回退；详见各里程碑文档。
- **AMT/Wyckoff 语义复刻**：ARK 测试样本作为基线，但数据存储模型从 BadgerDB 迁到 Postgres，字段需要重新对齐。
- **AI 凭据策略**：BYOK（用户密钥）与系统密钥的优先级在 `08-M5-AI编排.md` 中正式约定。
- **/health 与 crypto envelope 迁移**：影响容器探针与现有登录流；需要灰度切换计划，详见 `01-出口协议合规改造.md`。
