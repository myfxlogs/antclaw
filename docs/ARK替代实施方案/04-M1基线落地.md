## 4. T3 CoinGecko 薄 client + 修复 onchain records=0

### 4.1 创建薄 client

```
backend/internal/infra/apiclient/coingecko/
├── client.go
├── endpoints.go         # 常量： /coins/{id}/market_chart 等
├── types.go             # MarketChartResponse、CoinInfo 等
├── parse.go
├── errors.go
└── client_test.go
```

`Client.GetMarketChart(ctx, coinID, vsCurrency, days)` 返回 `[][]float64`（time, price, market_cap, volume）。

### 4.2 修复 records=0 根因

对照 `worker/collector_onchain.go` 现状：

```go
// 现状（伪码）
url := fmt.Sprintf(".../coins/%s/market_chart?...&days=30&interval=daily", asset.ID)
// 解析后写入 onchain_metrics 表
```

可能根因（按概率排序）：
1. **接口字段位置变化**：CoinGecko free tier 已移除 `interval` 参数，daily 默认为 90+ 天；解析的字段索引错位 → 0 records
2. **写入冲突**：`ON CONFLICT (asset, time) DO NOTHING`，但 `time` 时间戳未截断到日，重复写入被忽略
3. **过滤条件**：插入前的 `WHERE` 滤除了所有候选

### 4.3 修复步骤

1. 抽出到 `apiclient/coingecko/`，先编写 `client_test.go` 用真实 fixture（curl 一份样本响应保存到 `testdata/`）。
2. 在 `service/onchain/` 新建 `service.go`，把"取数 + 入库"逻辑迁过来，并加入：
   ```go
   logger.Info("coingecko response", "asset", asset.ID, "rows", len(prices), "first_ts", prices[0][0])
   ```
3. 修正字段：CoinGecko 返回 `prices`、`market_caps`、`total_volumes` 三组数组；每组元素为 `[ts_ms, value]`。
4. 时间统一为 `time.UnixMilli(int64(ts)).UTC().Truncate(24*time.Hour)`，避免 ON CONFLICT 错配。
5. 改 worker 的 collector：调用 `service/onchain.Sync(ctx, assets)`，返回 `inserted` 与 `skipped`，记入日志。
6. 在 `proto/antclaw/v1/onchain.proto` 落地 `OnchainService`（详见 03 文档）。

### 4.4 验收

```bash

# 期望：records>0；inserted>0
docker exec antclaw-postgres psql -U antclaw -d antclaw -c "SELECT asset, COUNT(*) FROM onchain_metrics GROUP BY 1;"

```

## 8. T7 CryptoService.PostEnvelope

按 `01-出口协议合规改造.md` §3 执行。

**关键实现**：内层路由表

```go
type Router struct {
    User    userv1connect.UserServiceHandler
    AI      aiv1connect.AIServiceHandler
    // ... 全部 Service handler
}

func (r *Router) Dispatch(ctx context.Context, path string, body []byte) ([]byte, error) {
    switch path {
    case "antclaw.v1.UserService/UpdateSettings":
        var in v1.UpdateSettingsRequest
        if err := proto.Unmarshal(body, &in); err != nil { return nil, err }
        resp, err := r.User.UpdateSettings(ctx, connect.NewRequest(&in))
        if err != nil { return nil, err }
        return proto.Marshal(resp.Msg)
    // ...
    }
}
```

## 12. T10 存量 proto 体量审计（已完成）

### 12.1 审计结果

```bash
$ wc -l proto/antclaw/v1/*.proto | sort -n | tail
   209 proto/antclaw/v1/user.proto
   235 proto/antclaw/v1/backtest.proto
   268 proto/antclaw/v1/signals.proto
   285 proto/antclaw/v1/macro.proto
```

**结论**：全部源 `.proto` 文件 ≤ 285 行，无需拆分。

历史曾担忧的 15 个超标文件（`macro.pb.go` 2384 行等）均为 buf 生成的机械产物（`gen/` 目录），不在源代码 800 行硬上限审计范围。

### 12.2 修订规则

`scripts/lint-filesize.sh` 默认排除 `gen/`，仅审计源代码区：`backend/`、`frontend/`、`proto/`、`scripts/`、`deploy/`。理由见 `03-Proto契约新增清单.md` §1.1 修订说明。

### 12.3 后续防退化

- 新增 proto 必须在 800 行以内；若一个 Service 体量逼近上限，按子能力拆分（参考既有 `sentiment_extras.proto`、`macro_extras.proto` 命名）
- Service / Method 名稱不变，Go/TS 调用方无需改动
