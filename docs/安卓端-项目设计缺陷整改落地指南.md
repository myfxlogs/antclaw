# 安卓端项目设计缺陷整改落地指南

> 目标读者：Android 客户端 AI Agent  
> 适用范围：`frontend/android`  
> 上游依据：`docs/项目设计缺陷与工程化审查报告.md`  
> 专项依据：`docs/安卓端-在线状态与设备信息整改指南.md`  
> 不处理范围：Web 端、Admin 前端页面

---

## 一、整改目标

Android 端当前具备 Compose、Hilt、Connect-RPC、SSE、TokenStore、Room、ViewModel 等基础设施，但登录态、SSE、设备上报、信息流状态、发布体验和错误处理没有完全收口。

整改目标：

```text
会话唯一入口
  -> SSE 和设备上报稳定
  -> 信息流/发布/互动状态统一
  -> 错误与空态可恢复
  -> 文案资源化
  -> 单元测试覆盖高频路径
```

禁止继续通过局部布尔值、静默 catch、硬编码文案或伪造状态让页面“看起来可用”。

---

## 二、P0：会话、在线状态与设备信息

本部分按专项文档执行：`docs/安卓端-在线状态与设备信息整改指南.md`。

必须优先完成：

1. `AlfQApp` 改由 `SessionViewModel.session` 驱动根导航。
2. 登录/注册成功调用 `SessionViewModel.onLoginSuccess(...)`。
3. `MainContent` 前后台生命周期调用 `SessionViewModel.onForeground/onBackground()`。
4. `SessionViewModel` 统一负责 `sseClient.connect/disconnect/reconnect`。
5. 设备详情上报从登录成功链路触发，且失败可观测。
6. 区分基础 `device_id` 和详细设备采集 consent。

验收：

```text
登录成功
  -> SSE connected
  -> 管理端在线人数出现该用户
  -> 管理端设备列表出现该 device_id 且绑定用户
```

## 三、P0：Auth 数据流整改

### A-P0-01：AuthRepository 返回完整会话结果

当前 `AuthRepository.login/register` 返回 `Result<String>`，只包含 access token。

整改为：

```kotlin
data class AuthSessionResult(
    val userId: String,
    val accessToken: String,
    val refreshToken: String,
    val displayName: String = "",
    val codeId: String = "",
)
```

要求：

- `LoginResponse.userId/accessToken/refreshToken/codeId` 全部带出。
- `RegisterResponse.userId/accessToken/refreshToken/codeId` 全部带出。
- `AuthRepository` 不直接启动 SSE。
- `AuthRepository` 不直接维护根登录态。

### A-P0-02：根导航状态只认 SessionViewModel

禁止：

```kotlin
val isLoggedIn = remember { mutableStateOf(ConnectTransportProvider.getToken() != null) }
```

目标：

```kotlin
val session by sessionVm.session.collectAsStateWithLifecycle()
when (session.state) {
    SessionState.AUTHENTICATED -> MainContent(...)
    SessionState.UNAUTHENTICATED, SessionState.EXPIRED -> AuthNavHost(...)
    SessionState.UNKNOWN -> SplashOrLoading()
}
```

要求：

- `SessionEvent.RequireLogin` 清理业务导航栈。
- refresh 失败后必须回登录页。
- logout 后必须断开 SSE 并清 token。

## 四、P1：Feed / Social 信息流整改

### A-P1-01：合并重复信息流逻辑

当前重复：

- `ui/feed/FeedViewModel.kt`
- `ui/social/SocialFeedViewModel.kt`

两者都实现分页、刷新、点赞、分享、Snackbar、乐观更新和回滚。

目标：

```text
TimelineController / FeedUseCase
  -> loadFirstPage(tab/filter)
  -> refresh()
  -> loadMore()
  -> optimisticLike(postId)
  -> optimisticShare(postId)
```

ViewModel 只处理页面特定状态：

```text
FeedViewModel -> tab/filter + TimelineState
SocialFeedViewModel -> 如仍保留，只包装不同入口
```

统一状态：

```kotlin
data class TimelineState(
    val posts: List<PostUi> = emptyList(),
    val phase: AsyncPhase = AsyncPhase.Idle,
    val appendPhase: AsyncPhase = AsyncPhase.Idle,
    val nextCursor: String? = null,
    val hasMore: Boolean = true,
)
```

验收：

- 首屏失败显示错误和重试。
- append 失败不清空已有列表。
- 点赞失败回滚。
- 分享失败回滚。
- 快速重复点击不会导致计数错乱。

### A-P1-02：Tab 未实现时隐藏或禁用

文档要求“Tab 未实现时必须隐藏或禁用”。如果 `HomeFeedTab.FOLLOWING`、推荐算法或信号过滤没有真实后端支持，必须：

- 隐藏该 Tab；或
- 禁用并显示“暂不可用”；或
- 后端真实支持后再打开。

禁止 Tab 点击后展示同一份数据却不给用户提示。

## 五、P1：发布体验整改

### A-P1-03：PostScreen 补齐发布闭环

当前问题：

- 成功后只清空输入并延迟重置。
- 错误态“重试”只是 reset，不会重新提交。
- `signalPair` 没有显式入口。
- 没有草稿、字数限制、成功回流 Feed。

目标行为：

| 场景 | 行为 |
|---|---|
| 内容为空 | 发布按钮禁用 |
| 提交中 | 按钮 loading，禁止重复提交 |
| 成功 | 返回 Feed 并插入顶部，或显示“查看帖子” |
| 失败 | 保留草稿，显示错误，重试提交上次 payload |
| token 过期 | refresh；失败回登录 |

建议模型：

```kotlin
data class PostDraft(
    val content: String,
    val visibility: String,
    val signalPair: String = "",
    val signalDirection: String = "",
    val signalConfidence: Int = 0,
)
```

`PostViewModel` 保存 `lastFailedDraft`，重试时复用。

## 六、P1：SSE 与通知体验整改

### A-P1-04：SSE 只能由会话层管理

允许：

- `SessionViewModel` 调用 `SseClient.connect/reconnect/disconnect`。
- `NotificationViewModel` 被动 collect `SseManager.notifications` 和 `connected`。

禁止：

- `AuthRepository` 启动 SSE。
- `NotificationViewModel.onCleared()` 断开 SSE。
- 多个 ViewModel 各自 connect。

### A-P1-05：SSE 错误状态可观测

`SseManager` 需要暴露：

```kotlin
data class SseStatus(
    val state: ConnectionState,
    val retryCount: Int,
    val lastError: String? = null,
    val connectedAt: Instant? = null,
)
```

用于 Debug 页面/设置页展示，不展示 token。

验收：

- 无 token 不发起连接。
- 401 后通知 session expired，不无限重连。
- 网络失败指数退避。
- 前台恢复立即 reconnect。

## 七、P1：设备信息与隐私整改

### A-P1-06：基础设备信息不被详细 consent 阻断

分两级：

基础字段，登录必须提供：

- `device_id`
- `user_agent`
- `os_type=android`
- `app_version`

详细字段，可受 consent 控制：

- 屏幕
- 网络
- 电池
- fingerprint
- 其他诊断字段

建议新增：

```kotlin
fun collectBasicDeviceInfo(): Device.DeviceInfo
fun collectDetailedDeviceInfoOrNull(): Device.DeviceInfo?
```

登录成功后至少上报 basic。用户进入设备信息页并授权后，再上报 detailed。

### A-P1-07：设备信息页资源化和产品化

`DeviceInfoScreen.kt` 当前有硬编码英文文案。必须迁移到 `strings.xml`，并补齐中文等主要语言资源。

页面必须说明：

- 为什么收集设备信息。
- 收集哪些字段。
- 是否可撤回。
- 上次上报时间和状态。

## 八、P2：UI 结构和命名整改

### A-P2-01：底部导航命名与行为一致

当前 `BottomNavBarWithFAB` 没有 FAB。

二选一：

1. 实现真正的中心发布 FAB。
2. 重命名为 `BottomNavBar`。

如果要对标 X/Threads，建议实现中心发布按钮，并导航到 `post`。

### A-P2-02：文案和颜色规范

要求：

- 所有用户可见文案进入 `strings.xml`。
- 交易方向颜色统一从 theme 获取，不在页面硬编码。
- 错误文案面向用户，原始异常只进日志。

## 九、测试要求

### A-T01：必须补的单元测试

优先补：

- `SessionViewModelTest`
  - 登录成功连接 SSE 和上报设备。
  - session expired 清 token、断 SSE、发 RequireLogin。
  - foreground/background 重连/断开。
- `AuthRepositoryTest`
  - Login/Register 带 `ClientInfo.device_id/user_agent`。
  - 返回完整 `AuthSessionResult`。
- `DeviceRepositoryTest`
  - basic 上报不依赖详细 consent。
  - RPC 失败不阻断登录但可观测。
- `FeedViewModelTest`
  - append 失败不清空已有数据。
  - like/share 失败回滚。
- `PostViewModelTest`
  - 提交中防重复。
  - 失败保留草稿。
  - retry 重交上次 payload。
- `SseManagerBackoffTest`
  - 401 不无限重连。
  - 网络失败指数退避。

cd frontend/android
./gradlew testDebugUnitTest

1. `AuthSessionResult` 和 `SessionViewModel` 根接入。
2. SSE 前后台生命周期与 session expired 流程。
3. 设备 basic/detailed 上报拆分。
4. Feed/Social timeline 逻辑合并。
5. Post 发布闭环。
6. DeviceInfoScreen 文案资源化。
7. BottomNavBar 命名或 FAB 行为修正。
8. 补测试。

---

## 十一、禁止事项

- 禁止登录成功只设置 token，不进入 `SessionViewModel`。
- 禁止多个模块各自启动或关闭 SSE。
- 禁止设备上报失败完全静默。
- 禁止详细 consent 阻断基础 `device_id`。
- 禁止发布失败丢草稿。
- 禁止空态按钮 `onClick = {}`。
- 禁止硬编码用户可见英文文案。
- 禁止为了演示效果伪造在线状态、设备记录、帖子或信号。
