## 1. Walk-forward 优化

### 1.1 目标
对策略参数集合进行滚动窗口优化：用 IS 训练得最优参数，OOS 测试，重复多 fold，写入 `walkforward_history`。

### 1.2 算法
```
total_range = [from, to]
fold_count = N (默认 5)
window = (to - from) / fold_count

for k = 0..N-1:
    train_from = from + k*window
    train_to   = train_from + train_ratio*window     # 默认 0.7
    test_from  = train_to
    test_to    = train_from + window

    best_params, in_sample_sharpe = grid_search(strategy, params_grid, train_from, train_to)
    oos_result = engine.Run(strategy, best_params, test_from, test_to)
    save WalkforwardHistoryRow(fold_idx=k, ...)
```

### 1.3 RPC
```proto
service BacktestService {
  rpc RunWalkforward(RunWalkforwardRequest) returns (RunWalkforwardResponse);
  rpc GetWalkforwardResult(GetWalkforwardResultRequest) returns (GetWalkforwardResultResponse);
}
```

## 2. Bootstrap 回测

### 2.1 目标
对已有 `trades` 进行有放回重抽样 N 次，评估指标分布稳定性（Sharpe / MaxDD 的 5/50/95 分位）。

### 2.2 算法
```
trades = baseline_run.Trades
returns = [t.PnlPct for t in trades]
results = []
for i = 1..N:
    sample = bootstrap_sample(returns, len(returns))   # with replacement
    sharpe_i = sharpe(sample)
    maxdd_i  = simulate_max_drawdown(sample)
    results.append((sharpe_i, maxdd_i))
return percentiles(results, [5,50,95])
```

### 2.3 RPC
```proto
rpc RunBootstrap(RunBootstrapRequest) returns (RunBootstrapResponse);

message RunBootstrapRequest {
  string base_job_id = 1;          // 基线 backtest 的 job_id
  int32  iterations = 2;            // 默认 5000
  uint64 random_seed = 3;
}
message RunBootstrapResponse {
  double sharpe_p5 = 1;
  double sharpe_p50 = 2;
  double sharpe_p95 = 3;
  double maxdd_p5 = 4;
  double maxdd_p50 = 5;
  double maxdd_p95 = 6;
  int32  iterations = 7;
}
```

## 4. MFE / MAE（已在文档 07 trade 字段定义）

实现位置：`backend/internal/service/backtest/engine.go`，每个 bar 内：

```go
func updateExcursion(p *Position, bar Bar) {
    pnlNow := pnlOf(p, bar.Close)
    if pnlNow > p.MFE { p.MFE = pnlNow }
    if pnlNow < p.MAE { p.MAE = pnlNow }
    // 用 high/low 取极端
    if p.Side == "long" {
        if pnlOf(p, bar.High) > p.MFE { p.MFE = pnlOf(p, bar.High) }
        if pnlOf(p, bar.Low)  < p.MAE { p.MAE = pnlOf(p, bar.Low) }
    } else {
        // short 反之
    }
}
```

## 5. 成本模型

文件：`backend/internal/service/backtest/cost.go`

```go
type CostModel struct {
    SlippageBps        float64    // 单边
    SpreadBps          float64    // 总点差（成对计算）
    CommissionPerTrade float64    // USD/笔
    FundingRateProvider func(symbol string, ts time.Time) float64  // 加密永续 funding
}

// 入场实际成交价
func (c *CostModel) EntryPrice(intended float64, side string) float64 {
    slip := intended * c.SlippageBps / 10000
    spread := intended * c.SpreadBps / 20000  // 半边
    if side == "long"  { return intended + slip + spread }
    return intended - slip - spread
}

// 平仓实际成交价
func (c *CostModel) ExitPrice(intended float64, side string) float64 { /* 镜像 */ }

// 持仓期 funding 累积（仅永续）
func (c *CostModel) ApplyFunding(p *Position, bar Bar) float64 {
    if c.FundingRateProvider == nil { return 0 }
    rate := c.FundingRateProvider(p.Symbol, bar.Time)
    // 假设 8h funding 周期；按 bar interval 比例
    return p.Qty * p.EntryPrice * rate * bar.IntervalHours / 8
}
```

调用点：
- `engine.Run` 每个 bar 末调用 `ApplyFunding`，扣减 `capital`；
- 入场 / 平仓时使用 `EntryPrice` / `ExitPrice`。

## 6. 信号置信度校准（Logistic / Platt / Isotonic）

### 6.1 目标
基于 `signal_outcomes` + `unified_signals.unified_score`，训练校准模型，将原始 `unified_score` 转为可信概率。

写入 `signal_calibration` 表（已有）：
```sql
signal_calibration:
  signal_type, logistic_a, logistic_b, sample_size, win_rate, avg_return, updated_at
```

### 6.2 算法

#### Logistic / Platt（同形）
```
y = direction_match::int          # 0/1
x = unified_score                 # 原始
fit logistic regression: P(y=1|x) = 1/(1+exp(-(a*x+b)))
```

#### Isotonic
分桶并保单调增长，存储为分段函数。可用 PAV (Pool Adjacent Violators) 算法。

### 6.3 训练任务

文件：`backend/cmd/antclaw-worker/calibration_trainer.go`

调度：每天 04:00。
- 对每个 `signal_type`（unified / cot_extreme / quant_*）拉取过去 365 天 outcomes；
- 训练 logistic + 写入 `signal_calibration`；
- 训练 isotonic + 写入新表 `signal_calibration_isotonic`：

```sql
CREATE TABLE IF NOT EXISTS signal_calibration_isotonic (
    signal_type VARCHAR(64) NOT NULL,
    bucket_idx  INT NOT NULL,
    x_lower     DOUBLE PRECISION,
    x_upper     DOUBLE PRECISION,
    p_calibrated DOUBLE PRECISION,
    sample_size INT,
    updated_at  TIMESTAMPTZ,
    PRIMARY KEY (signal_type, bucket_idx)
);
```

### 6.4 应用

`signals/unified_compute.go` 在写入 `unified_signals.confidence` 时：
```
raw_conf = sigmoid(|unified_score|*4) * data_completeness
calib    = signal_calibration.GetLogistic("unified")
final_conf = 1 / (1 + exp(-(calib.A * unified_score + calib.B)))
```

如校准未训练 → 返回 raw_conf 并打标 `calibration_missing`。

## 7. 衰减分析 / 去重 / 基线对比 / 因子分解

### 7.1 衰减分析（Decay）
对回测 trades 按时间分桶（季度），观察每桶 Sharpe，验证策略是否衰减。
```
buckets = group_by(trades, t -> t.entry_time.quarter)
for q in buckets: sharpe_q = sharpe(returns_in_q)
plot/return decay_table
```

### 7.2 去重（De-overlap）
若同一信号在 5 个 bar 内连续触发，仅保留最强的一笔（按 unified_score 绝对值）。位置：`engine.go` 的 `signal_filter.go`。

### 7.3 基线对比（Baseline）
对每次回测**自动**额外跑一组：
- `baseline_buyhold`：永远满仓多
- `baseline_random`：随机入场（同样数量交易，固定种子）

输出附加在 `AdvancedMetrics.baseline_compare`：
```proto
map<string, BacktestSummary> baseline_compare = 6;
```

### 7.4 因子分解（Attribution）
对每笔 trade 计算 entry 时的 6 大因子值，回测后做 OLS：
```
pnl_pct ~ a + b1*momentum + b2*lowvol + b3*trend + b4*carry + b5*crowding + b6*residual
```
输出系数 + R² 写入 `backtest_results.detailed.attribution`。
