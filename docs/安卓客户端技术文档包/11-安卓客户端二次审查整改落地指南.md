## 一、关键约束

### 1.1 不整改项：登录密码明文显示

登录/注册密码输入保持明文可见是产品要求，不作为整改项。

AI Agent 禁止擅自将密码框改为默认隐藏、禁止添加强制密码遮罩逻辑。安全边界由以下措施保证：

- 只允许通过 HTTPS Connect-RPC 传输认证请求。
- 禁止在日志、崩溃上报、埋点中记录密码。
- 禁止将密码写入 DataStore、Room、SharedPreferences 或内存缓存对象。
- 登录失败错误文案不得回显用户输入的密码。

### 1.2 落地原则

- 先读对应功能文档和 proto，不猜接口。
- 不使用硬编码假数据作为 fallback。
- UI 失败时显示错误状态，不伪造成成功状态。
- 复杂页面必须保留 `Screen -> ViewModel -> Repository -> Rpc` 数据流。
- 每个整改项完成后必须增加或更新测试。
- 文档中标为 P0 的项优先于新功能。

## 二、P0：必须优先整改

### A11-P0-01：根会话状态补齐启动加载页

#### 问题描述

当前根导航容易把 `SessionState.UNKNOWN` 直接归入登录流程，启动恢复 token 时可能出现登录页闪烁，且 session expired 没有明确用户提示。

#### 影响范围

- App 冷启动体验
- 自动登录体验
- token 过期后的可解释性

#### 改进方法

根导航必须显式区分四类会话状态：

```text
UNKNOWN          -> 启动加载页 / Splash
AUTHENTICATED    -> 主导航
UNAUTHENTICATED  -> 登录注册导航
EXPIRED          -> 登录注册导航 + 登录过期提示事件
```

#### 可靠落地办法

1. 在 `AlfQApp` 或拆分后的 `RootApp` 中单独处理 `SessionState.UNKNOWN`。
2. 新增轻量 `SplashLoadingScreen`，只展示品牌与加载状态，不发起业务请求。
3. `SessionViewModel` 初始化时完成 token/userId 恢复后再切换为 `AUTHENTICATED` 或 `UNAUTHENTICATED`。
4. `EXPIRED` 状态通过一次性事件显示“登录已过期，请重新登录”。
5. 不允许在 `LoginScreen` 内重复执行根级自动登录逻辑。

#### 验收标准

- 冷启动存在 token 时不闪登录页。
- 无 token 时进入登录页。
- refresh 失败时清 token、断 SSE、进入登录页，并有过期提示。
- 增加 `SessionViewModelTest` 覆盖 UNKNOWN 到目标状态的转换。

### A11-P0-02：Feed 首屏四态与分页错误态补齐

#### 问题描述

Feed 页面只明确处理 loading，首屏失败或空数据时可能显示空白；分页失败也缺少可恢复交互。

#### 影响范围

- 首页核心体验
- 弱网体验
- 用户对内容服务可用性的判断

#### 改进方法

Feed 状态拆为首屏状态和追加状态：

```text
initialPhase: idle/loading/success/empty/error
appendPhase: idle/loading/error
posts: List<PostUi>
nextCursor: String?
hasMore: Boolean
```

#### 可靠落地办法

1. 在 `FeedViewModel` 或 `TimelineController` 中统一维护 `TimelineState`。
2. 首屏加载失败时保留错误信息和重试动作。
3. 首屏成功但无数据时显示空态，不显示空白页。
4. 分页失败不得清空已有列表，只在列表底部显示“加载失败，点击重试”。
5. `loadMore()` 必须判断 `hasMore`、`appendPhase != loading`、`initialPhase == success/empty`。
6. UI 层使用 `snapshotFlow` 时必须 `distinctUntilChanged()`，避免重复触发分页。

#### 验收标准

- 首屏 loading 显示加载组件。
- 首屏 error 显示错误和重试按钮，点击后重新请求第一页。
- 首屏 empty 显示空态文案。
- append error 不清空已加载帖子。
- 快速滑到底部不会并发发起多个 `loadMore()`。
- 增加 `FeedViewModelTest` 覆盖首屏错误、空态、分页失败、防重入。

### A11-P0-03：发布帖子闭环补齐

#### 问题描述

发布成功、失败、重试、草稿、回流 Feed 的行为必须形成闭环，不能只清空输入或 reset 状态。

#### 影响范围

- 内容生产核心链路
- 用户数据丢失风险
- 社交活跃度

#### 改进方法

定义发布草稿和发布状态：

```text
PostDraft(content, visibility, signalPair, signalDirection, signalConfidence)
PostSubmitState(idle/loading/success/error)
lastFailedDraft: PostDraft?
```

#### 可靠落地办法

1. `PostViewModel` 维护当前草稿，输入变化实时更新。
2. 内容为空时禁用发布按钮。
3. 提交中禁用重复点击。
4. 失败时保留草稿和 `lastFailedDraft`。
5. 重试必须重新提交 `lastFailedDraft`，不得只是清错误状态。
6. 成功后返回 Feed 并触发顶部插入，或跳转帖子详情。
7. 如果关联信号发帖入口未实现，隐藏相关选项；不得展示无效入口。

#### 验收标准

- 发布失败后输入内容不丢失。
- 点击重试会重新调用创建帖子 RPC。
- 发布成功后用户能看到新帖子或进入详情页。
- 快速重复点击只发起一次发布请求。
- 增加 `PostViewModelTest` 覆盖成功、失败保留草稿、重试、重复点击。

### A11-P0-04：错误展示从异常透传改为用户友好映射

#### 问题描述

直接展示 `Exception.message` 容易出现英文技术细节、RPC path、HTTP 信息，也可能泄露内部实现。

#### 影响范围

- 登录/注册
- Feed、发布、通知、资料页等所有 RPC 页面
- 安全与品牌体验

#### 改进方法

建立统一错误映射：

```text
Rpc/IOException/Auth/Validation/Unknown
  -> AppError
  -> string resource
  -> UI 展示
```

#### 可靠落地办法

1. 新增 `data/error/AppError.kt` 或等价文件。
2. 在 RPC/Repository 边界把异常转换为领域错误。
3. ViewModel 只暴露用户可读错误 key 或已资源化文案。
4. 技术详情只写日志，不直接进入 UI。
5. 所有错误文案进入 `strings.xml`，不得硬编码。

#### 验收标准

- 网络断开显示“网络连接失败，请检查后重试”。
- 401/登录过期显示“登录已过期，请重新登录”。
- 服务端 5xx 显示“服务暂不可用，请稍后重试”。
- UI 不出现 RPC path、stack trace、英文异常类名。
- 登录、注册、Feed、发布至少各有一条错误映射测试。

## 三、P1：短期体验与工程整改

### A11-P1-01：主题系统补齐深色模式

#### 改进方法

`AlfQTheme(darkTheme = ...)` 必须实际切换浅色/深色 `ColorScheme`。

#### 可靠落地办法

1. 在 `Theme.kt` 增加 `AlfQDarkColors`。
2. 使用 `if (darkTheme) AlfQDarkColors else AlfQLightColors`。
3. 检查品牌金、信号涨跌色、错误色在深色背景下的对比度。
4. 关键页面在浅色/深色分别截图自测。

#### 验收标准

- 系统切深色后 App 背景、卡片、文本均切换为深色体系。
- 文本对比度满足可读性要求。
- 不出现白底白字、黑底黑字。

---

### A11-P1-02：统一页面结构和底部导航语义

#### 改进方法

优先使用 Material3 标准组件：`Scaffold`、`TopAppBar`、`NavigationBar`、`NavigationBarItem`。

#### 可靠落地办法

1. 将自定义底部 `Row + clickable` 替换或封装为标准导航项。
2. 统一返回栏：普通页面使用 `TopAppBar` 的 navigation icon。
3. 菜单箭头使用标准 icon，不使用字符串 `>`。
4. 所有可点击图标提供 `contentDescription`。

#### 验收标准

- TalkBack 能读出底部每个 Tab 名称和选中状态。
- 视觉上各页面顶部栏高度、返回位置一致。
- 底部导航 badge 有可读语义。

---

### A11-P1-03：国际化与文案资源化

#### 改进方法

所有 UI 可见文案必须进入资源文件，禁止 Screen 中硬编码中文或英文。

#### 可靠落地办法

1. 扫描 `ui/**` 中硬编码字符串。
2. 将 Tab、按钮、错误、空态、成功提示加入 `values/strings.xml`。
3. 同步更新现有多语言目录；暂无法翻译时使用英文或中文基准，但 key 必须存在。
4. Repository 不返回 UI fallback 文案，只返回结构化状态。

#### 验收标准

- `FeedScreen` 不再硬编码“关注/推荐/信号/搜索/通知”等文案。
- 登录、发布、Feed 错误和空态文案全部资源化。
- 切换语言后主要导航和核心页面文案变化。

---

### A11-P1-04：SSE 连接复用、网络感知与状态可观测

#### 改进方法

SSE 只由会话层管理，网络层单例复用 OkHttpClient，通知中心可以观察连接状态。

#### 可靠落地办法

1. 将 SSE `OkHttpClient` 通过 Hilt 单例注入。
2. `SseManager` 不在每次连接时创建新 client。
3. 接入 `ConnectivityManager.NetworkCallback` 或等价网络状态源。
4. 无网时暂停重连；网络恢复后由会话层触发 reconnect。
5. `NotificationViewModel` 只 collect 连接状态，不主动 connect/disconnect。
6. 通知中心显示“实时连接中/已断开/重连中”的轻量状态。

#### 验收标准

- 前后台切换不会产生多个 SSE 连接。
- 无网时不会持续高频重连。
- 网络恢复后自动重连。
- 通知中心能体现连接异常。
- `SseManagerBackoffTest` 增加无网暂停和恢复重连测试。

---

### A11-P1-05：Repository 和导航职责拆分

#### 改进方法

按单一职责拆文件，避免聚合文件承载多个业务域。

#### 可靠落地办法

1. 将 `ExtraRepositories.kt` 拆成独立 Repository 文件。
2. 将主导航路由字符串集中到 `navigation/Routes.kt`。
3. 将 `AlfQApp.kt` 拆为根入口、认证导航、主导航、通知跳转处理。
4. 拆分时只移动代码，不改变业务行为；先保证测试通过。

#### 验收标准

- 每个 Repository 文件只负责一个业务概念。
- 新增页面路由不需要修改多个字符串散落点。
- `AlfQApp.kt` 只保留根主题和根状态分流职责。

---

### A11-P1-06：Token 与 RPC 调用性能优化

#### 改进方法

避免在 OkHttp 拦截器中频繁 `runBlocking` 读取 DataStore；access token 使用内存快照，DataStore 只做持久化来源。

#### 可靠落地办法

1. `ConnectTransportProvider` 初始化时从 `TokenStore` 恢复 token 到内存。
2. 登录/refresh 成功后同时更新内存 token 和持久化 token。
3. 拦截器只读取内存 token，不直接阻塞 DataStore。
4. refresh 继续保持 single-flight，失败后通知 session expired。
5. 所有 RPC 调用统一走可测试的 client/provider。

#### 验收标准

- 并发 RPC 不会并发触发多个 refresh。
- refresh 成功后失败请求能重试一次。
- refresh 失败后清 token、断 SSE、回登录页。
- `ConnectTransportProviderRefreshTest` 覆盖并发 401 场景。

## 四、P2：工程治理与质量保障

### A11-P2-01：补齐无障碍支持

#### 改进方法

关键交互组件必须具备语义、角色、状态和可读描述。

#### 可靠落地办法

1. 加载组件增加语义描述或 test tag。
2. 错误、成功、登录过期提示使用 live region。
3. 导航项声明选中状态。
4. 图标按钮必须提供 `contentDescription`。
5. 列表卡片点击区域必须可被 TalkBack 识别。

#### 验收标准

- TalkBack 可完成登录、浏览 Feed、进入详情、返回、打开通知。
- 加载/错误状态能被读屏感知。
- Compose UI 测试能通过语义节点定位关键状态。

---

### A11-P2-02：测试覆盖补齐

#### 改进方法

测试必须覆盖高频路径和每个整改项，不只测 happy path。

#### 可靠落地办法

优先新增以下测试：

- `SessionViewModelTest`：启动恢复、过期、登出、前后台 SSE。
- `FeedViewModelTest`：首屏错误、空态、分页失败、防重入。
- `PostViewModelTest`：草稿保留、重试、成功回流、重复点击。
- `ConnectTransportProviderRefreshTest`：并发 401 single-flight。
- Compose UI 测试：Feed 错误态、空态、登录错误、通知连接状态。

#### 验收标准

- 每个 P0 整改至少有 1 个单元测试或 UI 测试。
- 弱断言测试不得只验证某文本不存在，必须验证目标状态存在。
- 测试不得依赖真实网络。

---

### A11-P2-03：构建与 CI 文档化

#### 改进方法

Android 端必须有可重复执行的本地命令和 CI 命令。

#### 可靠落地办法

1. 在 Android 文档中固定以下命令：

```bash
./gradlew :app:assembleDebug
./gradlew :app:testDebugUnitTest
./gradlew :app:lintDebug
```

2. Release 构建必须校验签名配置。
3. 依赖版本尽量进入 `libs.versions.toml`。
4. release 建议启用资源压缩。

#### 验收标准

- 本地执行 assemble/test/lint 通过。
- CI 或脚本文档能被 AI Agent 直接照做。
- 缺少签名信息时 release 发布任务 fail-fast，而不是静默产出不可发布包。

---

### A11-P2-04：文档与代码状态一致性维护

#### 改进方法

整改文档中的 checklist 必须真实反映代码状态，不能把未验证项标为完成。

#### 可靠落地办法

1. 每完成一个整改项，在对应文档中将 `[ ]` 改为 `[x]`。
2. 标记完成时必须写明代码文件和测试文件。
3. 如果发现旧文档与代码不一致，新建“复核备注”而不是直接删除历史内容。
4. 不确定功能是否真实接入后端时，保持 `[ ]`，并写明待验证点。

#### 验收标准

- 文档 checklist 中每个 `[x]` 都能追溯到代码和测试。
- AI Agent 后续开发不会依据错误完成状态跳过整改。

- 用户失败路径可恢复。
- 添加或更新了对应测试。
- 通过本地构建/测试/ lint。

### 8.4 测试基础设施重构

| 新增文件 | 用途 |
|---|---|
| `testutil/CoroutineTestBase.kt` | 协程测试基类（提供 `scheduler` + `MainDispatcherRule`） |

| `data/rpc/TokenManager.kt` | Token 生命周期管理器 — 从 `ConnectTransportProvider` 分离 |

**职责拆分后的架构：**
- `TokenManager`（DI @Singleton）：Token 缓存/持久化/刷新/session-expired 通知
- `ConnectTransportProvider`（传输层）：OkHttp 拦截器 + ProtocolClient 创建
- `SseManager`（DI @Singleton）：通过 DI 注入 `TokenManager`，token 解耦
- `SessionViewModel`（DI @HiltViewModel）：注入 `TokenManager` 替代直接调 `ConnectTransportProvider.init/setToken/clearToken`
- `AlfQApplication`：删除 `@Inject TokenStore` 和手动 `ConnectTransportProvider.init()`，完全由 DI 管理
