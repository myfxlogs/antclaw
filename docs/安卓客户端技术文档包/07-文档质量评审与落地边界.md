# 文档质量评审与落地边界

## 一、评审结论

当前文档包已经完成全量技术扫描，覆盖 `39` 个 Service、`229` 个 RPC、SSE 通知入口、Android 分层与 AI Agent 执行规则。它可以作为客户端 AI Agent 的开发入口，但必须结合本文的边界说明使用。

最终判断：

| 评审项 | 结论 | 说明 |
|---|---|---|
| 接口覆盖完整性 | 通过 | `01` 和 `02` 已覆盖 proto 中全部 Service/RPC |
| Android 独立开发方向 | 通过 | 统一使用 `https://api.alfq.org/`，禁止访问管理端域名和端口 |
| AI Agent 可读性 | 基本通过 | 已有索引、总览、字段参考、SSE、客户端指导、执行指南 |
| 直接代码落地充分性 | 需要本文补强 | 需要明确“哪些接口 Android 必做、哪些禁止做、哪些暂不做” |
| 逻辑冲突 | 已识别并规避 | 管理端接口与客户端接口同在 API 文档中，必须按范围字段区分 |

## 二、已发现的潜在歧义

### 2.1 `01-API接口总览.md` 是“全量接口清单”，不是“Android 必须全部实现清单”

`01-API接口总览.md` 为避免遗漏，列出了所有已注册或已定义的接口，其中包含：

- Android 客户端接口。
- 管理端接口。
- 运维/系统接口。
- 尚未在 Android 当前阶段实现的扩展接口。

AI Agent 不能看到接口就实现页面。必须先判断 `范围` 字段：

| 范围 | Android 行为 |
|---|---|
| `客户端/通用` | 可按功能需求接入 |
| `管理端` | 禁止在 Android 客户端实现，除非用户明确改变产品边界 |
| `API 入口注册：否/需确认` | 禁止直接落地，先确认后端是否注册 |

### 2.2 `02-API字段参考.md` 的字段必填规则不等于最终业务校验

proto3 不支持传统 required 语义，所以字段表中的“是否必填”默认写为：

```text
否；proto3 默认值语义，业务必填以服务端校验为准
```

这不是说字段都可以不传。AI Agent 实现时必须遵守：

- 登录邮箱/密码等明显业务字段必须传。
- 分页参数按页面需要传；未定义默认值时不要猜，先用后端既有示例或提问。
- 枚举字段必须使用 proto 生成类型，禁止硬编码魔法字符串。
- 业务约束不清晰时，不能伪造默认值掩盖问题。

### 2.3 `StreamService` 不作为当前 Android 主路径

扫描结果中 `StreamService` 未在 API 入口注册。当前实时能力以 HTTP SSE 为准：

```text
GET https://api.alfq.org/sse/notifications
```

因此 Android 当前阶段必须实现 `NotificationSseClient`，不要实现 `StreamService/SubscribeEvents` 作为主路径。

### 2.4 `api.alfq.org` 是客户端唯一服务端入口，但不代表所有 Service 都面向 Android

`api.alfq.org` 承载 Connect-RPC 与 SSE，但 Android 仍必须遵守产品边界：

- 不实现 AdminService。
- 不实现 AdminDataService。
- 不实现 DataSourceService。
- 不实现 SystemAIService 管理配置能力。
- 不直接暴露运维、审计、后台任务控制能力。

## 三、Android 客户端接口优先级矩阵

### 3.1 P0：客户端基础闭环，必须优先实现

| 模块 | Service / Endpoint | 说明 |
|---|---|---|
| 系统健康 | `SystemService/Healthz` | Debug/诊断用，验证 API 域名可达 |
| 认证 | `AuthService/Login` | 登录入口 |
| 认证 | `AuthService/Register` | 注册入口，如产品开放注册 |
| 认证 | `AuthService/Refresh` | access token 过期刷新 |
| 认证 | `AuthService/Logout` | 退出登录 |
| 当前用户 | `UserService/GetMe` | 获取个人信息 |
| 通知未读 | `NotificationService/UnreadCount` | 底部 Badge 与通知中心入口 |
| 通知列表 | `NotificationService/ListUnread`、`NotificationService/ListHistory` | 通知中心 |
| 通知已读 | `NotificationService/MarkRead`、`NotificationService/MarkAllRead` | 已读状态同步 |
| 实时通知 | `/sse/notifications` | 前台实时推送 |

### 3.2 P1：核心业务页面

| 模块 | Service | 说明 |
|---|---|---|
| Feed | `FeedService` | 首页内容流 |
| 交易员 | `TraderService` | 交易员资料、关注、动态 |
| 信号 | `SignalsService` | 信号列表与详情 |
| 行情 | `PriceService` | 价格与行情数据 |
| 告警 | `AlertService` | 用户告警订阅、创建、列表 |
| MT 账户 | `MT4Service`、`MT5Service` | 账户绑定与展示，按当前产品范围接入 |

### 3.3 P2：发现页与高级数据

| 模块 | Service | 说明 |
|---|---|---|
| 宏观 | `MacroService`、`MacroExtrasService`、`CalendarService` | 发现页宏观数据 |
| COT | `COTService` | COT 偏向 |
| Regime | `RegimeService` | 市场状态 |
| 期权 | `OptionsService`、`VolService` | GEX、IV、VIX 等 |
| 链上 | `OnchainService`、`DeFiService` | 加密市场扩展 |
| 情绪 | `SentimentService`、`SentimentExtrasService` | 市场情绪扩展 |

### 3.4 禁止 Android 默认实现的接口

| Service | 原因 |
|---|---|
| `AdminService` | 管理端能力，涉及用户、任务、审计、强制退出 |
| `AdminDataService` | 管理端数据检查能力 |
| `DataSourceService` | 数据源密钥/配置管理，属于后台管理 |
| `SystemAIService` | 系统 AI 配置与密钥管理，属于后台管理 |
| `/sse/jobs` | 后台任务事件，管理端用途 |
| `/sse/audit` | 审计事件，管理端用途 |

## 四、AI Agent 代码落地执行规则

### 4.1 实现任何页面前必须回答的问题

AI Agent 在写代码前必须明确：

1. 当前页面属于 P0、P1 还是 P2？
2. 使用哪个 Service / RPC？
3. 请求和响应字段在 `02-API字段参考.md` 的哪个章节？
4. 是否需要登录态？
5. 是否需要本地缓存？
6. 失败时 UI 如何显示？
7. 是否涉及 SSE 或未读数刷新？

如果其中任一问题无法回答，不能直接写代码。

### 4.2 标准落地链路

```text
确认功能优先级
  → 查 01 API 总览
  → 查 02 字段参考
  → 查 04 客户端开发指导
  → 如涉及通知查 03 SSE
  → 写 data/rpc 封装
  → 写 Repository
  → 写 ViewModel UiState
  → 写 Compose Screen 四态 UI
  → 增加错误处理
  → 运行构建/测试
```

### 4.3 错误处理必须统一

| 场景 | 客户端行为 |
|---|---|
| `401` | 先尝试 Refresh；失败后清理 token 并跳转登录 |
| `403` | 显示无权限，不重试 |
| 参数错误 | 标记输入错误，不重试 |
| 网络错误 | 使用缓存并显示重试入口 |
| 服务端错误 | 显示错误状态，允许用户重试 |
| SSE 断开 | 指数退避重连，App 回前台补拉未读 |

## 五、当前文档包能否作为代码落地依据

可以，但必须满足以下使用方式：

- 以 `00-文档索引.md` 作为入口。
- 以本文作为接口范围和优先级边界。
- 以 `01-API接口总览.md` 查询端点。
- 以 `02-API字段参考.md` 查询字段。
- 以 `04-客户端开发指导.md` 约束 Android 架构。
- 以 `06-AI-Agent执行指南.md` 约束 AI Agent 开发行为。

如果 AI Agent 只读 `01` 和 `02`，仍可能产生“把管理端接口做进 Android”的误解。因此本文是必读文档。

## 六、仍需后续人工确认的事项

以下内容无法仅靠 proto 全自动推断，需要后续根据产品设计或 handler 继续细化：

- 每个业务字段的严格必填规则。
- 分页默认值与最大值。
- 某些接口的会员等级限制。
- 某些高级市场数据是否对普通用户开放。
- Feed、Trader、Chat、Circle 等社交模块的当前产品优先级。
- Android 是否开放注册，还是只允许已有账号登录。

在这些事项确认前，AI Agent 不得自行发明规则。
