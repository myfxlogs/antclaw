# 产品设计与历史方案归档说明

## 归档目的

本目录用于集中存放 Android 客户端相关的产品设计、里程碑规划和历史改造方案，避免散落在 `docs/` 根目录。

## 文件说明

| 路径 | 是否保留 | 用途 |
|---|---|---|
| `AlfQ-安卓客户端设计文档.md` | 保留 | AlfQ Android 产品定位、信息架构、功能矩阵和总索引 |
| `alfq/` | 保留 | M0-M5 里程碑拆分文档与构建指南 |
| `客户端独立物理机开发改造方案.md` | 保留 | Android 独立物理机开发、API 域名、协议分发、联调方案 |
| `客户端智能推送方案.md` | 保留 | Android 智能通知、SSE、系统通知、未读补偿的设计依据 |
| `客户端智能推送-实施完成报告.md` | 保留 | 智能推送阶段性实施结果与验收记录 |
| `历史方案实现状态清单.md` | 保留 | 标记各历史方案是否已完成、部分完成、规划参考或当前执行依据 |

## 使用建议

- 新开发任务优先阅读上级目录的 `00-文档索引.md`、`07-文档质量评审与落地边界.md` 和 `09-服务端配套改造优化文档.md`。
- 本目录文档作为产品背景、历史决策和里程碑拆解依据。
- 如果本目录内容与上级技术文档包冲突，以上级技术文档包为准。

## 状态维护规则

- 已完成项目必须在对应文档顶部添加 `归档状态`。
- 未完成或未核验项目不得标记为已完成。
- AI Agent 开始实现前必须先查看 `历史方案实现状态清单.md`。
