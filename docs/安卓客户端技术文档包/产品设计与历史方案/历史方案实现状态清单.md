# 历史方案实现状态清单

## 一、用途

本文用于标记 `产品设计与历史方案/` 目录内文档的当前状态，避免 AI Agent 把已经完成的历史方案重复实现，或把规划文档误判为已完成代码。

## 二、状态定义

| 状态 | 含义 | AI Agent 行为 |
|---|---|---|
| `已完成归档` | 已有实施报告或明确验收结果 | 只读参考，不作为新待办 |
| `规划参考` | 产品规划、里程碑拆解、历史设计 | 可用于理解目标，但不能认定已实现 |
| `部分完成/待核验` | 可能已有部分代码，但文档验收项未全部闭环 | 先查代码和测试，再决定是否继续实现 |
| `当前执行依据` | 当前阶段正在使用的技术约束 | 必须优先遵守 |

## 四、服务端改造阅读顺序

如果当前目标是“先改造服务端”，阅读顺序如下：

1. `../09-服务端配套改造优化文档.md`
2. `../07-文档质量评审与落地边界.md`
3. `../01-API接口总览.md`
4. `../02-API字段参考.md` 中与本次任务相关的 Service/RPC
5. `客户端独立物理机开发改造方案.md` 的域名、协议分发、联调章节
6. 如涉及通知，阅读 `客户端智能推送-实施完成报告.md`，不要重新执行 `客户端智能推送方案.md`

## 五、AI Agent 使用规则

- 看到 `已完成归档` 文档时，只能用于查背景和验收，不得把其中任务重新列为待办。
- 看到 `规划参考` 文档时，必须先核验代码和测试，不能假定已经实现。
- 看到 `部分完成/待核验` 文档时，必须先查对应代码、proto、测试和运行结果。
- 如果状态清单与上级技术文档包冲突，以上级技术文档包为准。
