# 服务端配套改造优化文档

## 一、结论

Android 客户端文档已明确以 `https://api.alfq.org/` 作为唯一 API 入口。服务端当前已经具备大部分基础能力：

- Connect-RPC 服务已集中注册在 `backend/cmd/antclaw-api/main.go`。
- 个人通知 SSE 已存在 `/sse/notifications`。
- SSE 鉴权已支持 `Authorization: Bearer <token>`。
- 后端内部监听 `:8080`，可通过 Docker 宿主机端口与 Cloudflare Tunnel 暴露。

但是，为了让 Android 客户端 AI Agent 能稳定落地，服务端仍建议做配套改造与治理，重点不是新增业务接口，而是强化公共 API 域名、鉴权边界、协议版本、SSE 可观测性和回归测试。

## 二、必须处理的问题

### 2.1 Android 当前代码域名与文档不一致

当前 Android 代码中存在：

```text
frontend/android/app/build.gradle.kts
```

实际配置为：

```kotlin
buildConfigField("String", "BASE_URL", "\"https://app.alfq.org/\"")
```

但客户端文档统一要求：

```text
https://api.alfq.org/
```

处理要求：

- Android 客户端必须改为 `https://api.alfq.org/`。
- 服务端文档、联调脚本、冒烟测试必须统一使用 `https://api.alfq.org/`。
- `app.alfq.org` 不再作为 Android API 域名，避免与 Web/App 展示域混淆。

### 2.2 `api.alfq.org` 暴露全量 RPC，需要明确管理接口安全边界

当前 API 入口注册了客户端接口和管理端接口，例如：

- `AdminService`
- `AdminDataService`
- `DataSourceService`
- `SystemAIService`

这些接口可以存在于同一个 API 进程，但必须满足：

- 未登录请求必须返回 `401`。
- 非管理员请求必须返回 `403`。
- 管理接口不得因公开域名暴露而绕过权限。
- Android 客户端文档禁止实现管理端接口，但服务端仍必须做强校验，不能只依赖客户端自律。

### 2.3 协议版本和客户端兼容性缺少服务端可查询入口

Android 独立开发需要知道当前服务端兼容的协议版本。现有 `SystemService/Info` 可作为基础，但建议明确返回：

- API 版本。
- proto 版本。
- build commit。
- server time。
- Android 最低兼容客户端版本。
- 是否维护模式。

如果已有字段不足，应扩展 `SystemService/Info` 或新增专门字段。

### 2.4 SSE 长连接需要更明确的生产级行为

`/sse/notifications` 已可用，但服务端需要保证：

- 未授权返回 `401`。
- 已授权连接立即返回可识别的连接事件或心跳。
- 心跳间隔稳定。
- 断开时释放 Redis 订阅。
- 日志记录 userID、连接建立、断开、错误原因。
- 不把敏感 token 写入日志。

### 2.5 缺少面向 `api.alfq.org` 的服务端冒烟测试

当前客户端文档依赖公共域名。如果没有自动化检查，Cloudflare Tunnel、路由、SSE、CORS/Headers、认证很容易漂移。

必须增加或完善脚本：

```text
scripts/smoke-api-domain.sh
```

覆盖：

- `SystemService/Healthz`。
- `SystemService/Info`。
- 未登录访问 `/sse/notifications` 返回 `401`。
- 登录接口可达。
- 使用 token 访问 `NotificationService/UnreadCount`。
- 非管理员访问管理端接口返回 `403` 或 `401`。

## 三、服务端改造任务清单

### P0：必须完成

| 编号 | 任务 | 文件/位置 | 验收标准 |
|---|---|---|---|
| S-01 | 统一公共 API 域名说明和联调脚本 | `docs/`、`scripts/` | 所有 Android 联调文档使用 `https://api.alfq.org/` |
| S-02 | 增加 `api.alfq.org` 冒烟测试脚本 | `scripts/smoke-api-domain.sh` | 能验证 Healthz、SSE 401、登录、通知未读、管理接口拒绝 |
| S-03 | 审计管理端 RPC 权限 | `backend/internal/adapter/rpc/*admin*`、auth interceptor | 非管理员不能调用管理接口 |
| S-04 | 确认 `/sse/notifications` Bearer 鉴权稳定 | `backend/cmd/antclaw-api/sse_auth.go`、`sse_handlers.go` | Android OkHttp SSE 携带 Authorization 可连接 |
| S-05 | 增强 System Info 协议版本信息 | `proto/antclaw/v1/system.proto`、`backend/internal/adapter/rpc/system_handler.go` | 客户端可读取服务端版本、proto 版本、build commit |

### P1：建议完成

| 编号 | 任务 | 文件/位置 | 验收标准 |
|---|---|---|---|
| S-06 | 增加 SSE 连接日志和安全日志规范 | `sse_handlers.go` | 记录连接/断开/错误，不记录 token |
| S-07 | 增加通知端到端测试 | `backend/internal/notify`、`scripts/e2e/` | 创建通知后可通过 ListUnread 查询，Redis 推送路径可验证 |
| S-08 | 形成 proto 发布版本文件 | `PROTO_VERSION` 或 `docs/` | Android 可明确当前兼容 proto 版本 |
| S-09 | 生成 Android 协议包发布流程 | CI / Buf / Maven | 不依赖客户端机器持有完整后端源码 |

### P2：后续优化

| 编号 | 任务 | 文件/位置 | 验收标准 |
|---|---|---|---|
| S-10 | 按客户端/管理端拆分 API 网关策略 | Cloudflare / 反向代理 | 可限制管理接口来源或增加额外保护 |
| S-11 | Connect-RPC 反射或接口元数据 | 后端 API | 客户端调试工具可发现服务 |

## 四、推荐实现顺序

```text
S-01 统一域名文档和脚本
  → S-02 增加公共域名冒烟测试
  → S-03 审计管理接口权限
  → S-04 验证 SSE Bearer 鉴权
  → S-05 增强 System Info 版本信息
  → S-06/S-07 增强日志和通知测试
```

## 五、AI Agent 实现要求

AI Agent 在执行服务端变更时必须遵守：

- Handler 不直接访问数据库，保持 `adapter/rpc → service → infra/postgres`。
- 新增或修改 proto 后必须执行 `buf generate`。
- 不手动编辑 `gen/`。
- 不返回合成数据。
- 管理接口权限必须在服务端强制校验，不能只依赖前端隐藏入口。
- SSE 不得在日志中打印 token。
- 修改后必须执行质量检查。

## 六、建议验收命令

后端本地质量检查：

```bash
cd backend && go vet ./... && go test ./... && go build ./...
```

文件大小与协议检查：

```bash
bash scripts/lint-filesize.sh
bash backend/scripts/lint-protocol.sh
```

公共域名冒烟测试：

```bash
bash scripts/smoke-api-domain.sh https://api.alfq.org
```

容器更新：

```bash
docker compose -f deploy/docker-compose.yaml --project-name antclaw up -d --build api worker admin
```

## 七、是否需要立即改服务端代码

当前不需要为了“让 Android 能连上 API”而大改服务端，因为 Connect-RPC 和 `/sse/notifications` 已存在。

但需要尽快完成以下服务端治理变更：

1. 增加 `api.alfq.org` 冒烟测试。
2. 审计管理端接口权限。
3. 增强 `SystemService/Info` 的版本信息。
4. 明确 proto/SDK 发布流程。
5. 增强 SSE 日志与测试。

这些变更会让 Android 客户端 AI Agent 在独立机器上开发时有稳定、可验证、可追踪的后端依据。
