# 客户端开发指导

## 一、交互边界

Android 客户端只允许访问：

```text
https://api.alfq.org/
```

禁止访问：

- `https://ad.alfq.org/`
- `http://localhost:8082`
- Docker 内部域名
- PostgreSQL / Redis

## 二、推荐 Android 分层

```text
ui/<feature>/Screen.kt        # 纯 UI 组合
ui/<feature>/ViewModel.kt     # 状态与事件
data/rpc/*Rpc.kt              # Connect-RPC 调用封装
data/notification/*           # SSE、系统通知、本地通知模型
data/local/*                  # Room 缓存
di/AppModule.kt               # 依赖注入
```

## 三、数据流转

```text
Screen 用户事件
  → ViewModel
  → Repository / Rpc 封装
  → ConnectTransportProvider
  → https://api.alfq.org/
  → antclaw-api
  → ViewModel 更新 UiState
  → Compose 重组
```

通知流：

```text
antclaw-worker / notify.Service
  → PostgreSQL notifications
  → Redis Pub/Sub
  → /sse/notifications
  → NotificationSseClient
  → Room + NotificationViewModel
  → Badge / 通知中心 / 系统通知
```

## 四、状态管理策略

统一使用四态模型：

| 状态 | 含义 | UI 行为 |
|---|---|---|
| `idle` | 未加载 | 显示占位或入口 |
| `loading` | 请求中 | 显示加载态 |
| `success` | 成功 | 显示数据 |
| `error` | 失败 | 显示错误与重试 |

禁止使用硬编码假数据作为 fallback。

## 五、认证策略

- 登录成功保存 `access_token` 与 `refresh_token`。
- 所有业务 RPC 请求添加 `Authorization: Bearer <access_token>`。
- `401` 触发 refresh；refresh 失败则清理登录态。
- SSE 与 RPC 使用同一 token provider。

## 六、UI 组件规范

- 使用 Jetpack Compose + Material3。
- 主题入口：`ui/theme/Theme.kt`。
- 主色使用 anttrader 金色/深石墨色系。
- 页面组件保持薄层，复杂业务放入 ViewModel/Repository。
- 通知 Badge 必须来自 `NotificationService/UnreadCount` 或本地缓存，不得硬编码。

## 七、性能优化

- 列表使用 LazyColumn。
- 网络请求放在 ViewModel scope。
- 前台补拉 + SSE 增量更新，避免轮询。
- Room 缓存通知和 Feed 列表。
- 图片使用 Coil 并开启缓存。

## 八、兼容性要求

- Android minSdk：以 `app/build.gradle.kts` 为准，当前为 26。
- JDK：17。
- 网络：Release 只允许 HTTPS。
- SSE：必须支持断线重连。

## 九、开发环境

- Android Studio
- JDK 17
- Gradle Wrapper
- API：`https://api.alfq.org/`

构建命令：

```bash
./gradlew assembleDebug
```
