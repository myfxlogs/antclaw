# 安卓端在线状态与设备信息整改指南

> 目标读者：Android 客户端 AI Agent  
> 适用范围：`frontend/android`  
> 当前目标：修复管理端无法正确看到客户端在线状态和设备信息的问题  
> 不处理范围：Web 端、Admin 页面重构

---

## 一、整改结论

当前 Android 端已经具备设备 ID、设备信息收集、SSE 管理器、SessionViewModel 等组件，但链路没有真正闭合：

1. 登录成功后只更新 `AlfQApp` 局部 `isLoggedIn`，没有接入 `SessionViewModel`，因此 SSE 不会由统一会话层启动。
2. `NotificationViewModel` 明确写着“SSE 连接由 SessionViewModel 统一管理”，但根组件实际没有创建/订阅 `SessionViewModel`。
3. `AuthRepository` 登录/注册成功后只异步 `reportDeviceInfo()`，注释也说 SSE 由 `SessionViewModel` 管理，但实际调用路径没有触发。
4. 详细设备信息上报依赖用户 consent；未授权时 `DeviceInfoCollector.collect()` 返回 null，导致管理端只能看到登录时的基础 `device_id`，甚至在服务端 bug 下可能被覆盖成无用户设备。

本次整改目标是让 Android 登录后稳定完成：

```text
Login/Register
  -> 保存 access_token / refresh_token / user_id
  -> 建立 /sse/notifications 长连接
  -> 管理端在线人数可见
  -> 异步上报设备详情
  -> 管理端设备列表可见且绑定到正确用户
```

## 二、当前代码断点

### 2.1 根登录态绕过 SessionViewModel

当前文件：`frontend/android/app/src/main/java/com/antclaw/alfq/AlfQApp.kt`

问题位置：

- `AlfQApp.kt:45`：`isLoggedIn` 直接从 `ConnectTransportProvider.getToken()` 初始化。
- `AlfQApp.kt:52-55`：登录成功只 `ConnectTransportProvider.setToken(token)` 并设置 `isLoggedIn=true`。
- `AlfQApp.kt:62-65`：注册成功同样只设置 token。
- `AlfQApp.kt:80`：前后台生命周期只通知 `NotificationViewModel.setForeground()`，没有通知 `SessionViewModel.onForeground/onBackground()`。

影响：

- `SessionViewModel.init` 中的 `sseClient.connect()` 不会可靠运行。
- `SessionExpiredNotifier` 的会话过期事件无法驱动根导航回登录页。
- App 前台恢复不会统一重连 SSE。

### 2.2 AuthRepository 注入了 SseClient 但不使用

当前文件：`frontend/android/app/src/main/java/com/antclaw/alfq/data/repository/AuthRepository.kt`

问题位置：

- `AuthRepository.kt:21` 注入 `private val sseManager: SseClient`，但没有调用。
- `AuthRepository.kt:88-93` 只异步上报设备信息，注释写明 SSE 由 `SessionViewModel` 管理。

影响：

如果根组件没有接入 `SessionViewModel`，登录后不会建立 SSE，管理端在线用户永远为空。

### 2.3 设备详情上报被 consent 阻断

当前文件：`frontend/android/app/src/main/java/com/antclaw/alfq/data/device/DeviceInfoCollector.kt`

问题位置：

- `DeviceInfoCollector.kt:83-85`：无 consent 直接返回 null。
- `DeviceRepository.kt:31-35`：collect 失败后跳过上报。

影响：

管理端至少能通过 Login/Register 的 `ClientInfo.device_id` 看到基础设备记录，但不会有品牌、型号、系统版本、App 版本、屏幕等详细字段。若服务端 `ReportDeviceInfo` 继续允许空 user_id 覆盖，则后续上报还可能破坏设备和用户的关联。

### 2.4 Login/Register 回调只返回 token

当前文件：

- `frontend/android/app/src/main/java/com/antclaw/alfq/ui/login/LoginViewModel.kt`
- `frontend/android/app/src/main/java/com/antclaw/alfq/ui/login/RegisterViewModel.kt`
- `frontend/android/app/src/main/java/com/antclaw/alfq/ui/login/LoginScreen.kt`
- `frontend/android/app/src/main/java/com/antclaw/alfq/ui/login/RegisterScreen.kt`

问题：

回调只传 `accessToken`，没有把 `userId`、`refreshToken`、`displayName/codeId` 传给会话层。虽然 `AuthRepository` 内部保存了 token，但根会话层缺少显式状态转换依据。

## 三、目标架构

### 3.1 会话状态唯一入口

整改后，Android 登录态必须只由 `SessionViewModel` 驱动。

```text
AlfQApp
  -> SessionViewModel.session
  -> AUTHENTICATED: MainContent
  -> UNAUTHENTICATED / EXPIRED: AuthNavHost
```

禁止在 `AlfQApp` 中继续维护独立 `remember { mutableStateOf(...) }` 登录态。

### 3.2 登录成功后的统一副作用

登录/注册成功后只允许一个入口处理副作用：

```text
SessionViewModel.onLoginSuccess(...)
  -> TokenStore.saveAccessToken
  -> TokenStore.saveRefreshToken
  -> TokenStore.saveUserId
  -> ConnectTransportProvider.setToken
  -> sseClient.connect
  -> DeviceRepository.reportDeviceInfoBestEffort
```

推荐将 `DeviceRepository` 注入 `SessionViewModel`，让设备上报也归入登录成功链路。这样 `AuthRepository` 只负责发 RPC 和返回响应，不负责跨模块副作用。

## 四、整改任务清单

### A-01：扩展 AuthRepository 返回登录结果

当前 `AuthRepository.login/register` 返回 `Result<String>`，只包含 access token。应改为返回结构体：

```kotlin
data class AuthSessionResult(
    val userId: String,
    val accessToken: String,
    val refreshToken: String,
    val displayName: String = "",
    val codeId: String = "",
)
```

要求：

- `login()` 从 `LoginResponse` 填充 `userId/accessToken/refreshToken/codeId`。
- `register()` 从 `RegisterResponse` 填充 `userId/accessToken/refreshToken/codeId`。
- `AuthRepository` 不再直接调用 `ConnectTransportProvider.setToken()`，除非短期兼容需要；最终由 `SessionViewModel` 统一处理。
- `AuthRepository` 不再注入 `SseClient`。
- `AuthRepository` 不再调用 `deviceRepository.reportDeviceInfo()`，除非在迁移期临时保留。最终由 `SessionViewModel` 统一触发。

### A-02：让 Login/Register ViewModel 回传完整会话结果

调整：

- `LoginViewModel.login(onSuccess: (AuthSessionResult) -> Unit)`
- `RegisterViewModel` 的 state 中保存 `AuthSessionResult?`，或用一次性事件传递。
- `LoginScreen` / `RegisterScreen` 的回调从 `(String) -> Unit` 改为 `(AuthSessionResult) -> Unit`。

验收：

- 登录成功路径不再只返回 token。
- 注册成功路径与登录成功路径一致。

### A-03：AlfQApp 接入 SessionViewModel

整改 `AlfQApp.kt`：

```kotlin
@Composable
fun AlfQApp(sessionVm: SessionViewModel = hiltViewModel()) {
    val session by sessionVm.session.collectAsStateWithLifecycle()

    AlfQTheme(darkTheme = isSystemInDarkTheme()) {
        when (session.state) {
            SessionState.AUTHENTICATED -> MainContent(
                onLogout = { sessionVm.logout() },
                sessionVm = sessionVm,
            )
            else -> AuthContent(
                onLoginSuccess = { result ->
                    sessionVm.onLoginSuccess(
                        userId = result.userId,
                        accessToken = result.accessToken,
                        refreshToken = result.refreshToken,
                        displayName = result.displayName,
                    )
                },
            )
        }
    }
}
```

要求：

- 使用 `collectAsStateWithLifecycle()`。
- 订阅 `sessionVm.events`，收到 `RequireLogin` 时清理导航栈并展示登录页。
- 不再直接调用 `ConnectTransportProvider.setToken()`。

### A-04：前后台生命周期必须通知 SessionViewModel

当前 `MainContent` 只调用 `notifVm.setForeground()`。

整改为：

```kotlin
LifecycleAware(
    onStart = {
        sessionVm.onForeground()
        notifVm.setForeground(true)
    },
    onStop = {
        sessionVm.onBackground()
        notifVm.setForeground(false)
    },
)
```

验收：

- App 切到前台时，已登录用户会重连 SSE 并补拉未读。
- App 切到后台时断开 SSE，服务端 presence 会下线。

### A-05：SessionViewModel 负责设备详情上报

建议修改：

```kotlin
@HiltViewModel
class SessionViewModel @Inject constructor(
    private val tokenStore: TokenStoreApi,
    private val sseClient: SseClient,
    private val sessionNotifier: SessionExpiredNotifier,
    private val deviceRepository: DeviceRepository,
) : ViewModel()
```

在 `onLoginSuccess` 中：

```kotlin
setSession(SessionState.AUTHENTICATED, userId, displayName)
sseClient.connect()
deviceRepository.reportDeviceInfoBestEffort()
```

要求：

- 设备上报失败不能阻断登录。
- 上报失败要记录日志，并暴露 Debug 状态，便于开发联调。

### A-06：区分“基础设备标识”和“详细设备信息 consent”

必须明确：

- `device_id`、`user_agent` 是登录必要技术字段，不需要弹出详细设备采集授权。
- 详细设备信息，如型号、屏幕、网络、电池等，可受 consent 控制。

当前 `DeviceInfoCollector.collect()` 无 consent 时返回 null，导致详细上报跳过。整改有两种选择：

方案 1：登录后只上报非敏感基础字段。

```kotlin
fun collectBasic(): DeviceInfo {
    return DeviceInfo(
        deviceId = getDeviceId(),
        model = Build.MODEL,
        brand = Build.BRAND,
        osVersion = Build.VERSION.RELEASE,
        osType = "android",
        appVersion = getAppVersionName(),
        buildNumber = getAppVersionCode().toString(),
        // 不采集电池、网络、屏幕等扩展字段
    )
}
```

方案 2：保留 consent，但登录后只依赖 Login/Register 的 `ClientInfo.device_id` 建立基础记录；设备信息页授权后再上报完整信息。

推荐：短期采用方案 1，保证管理端可诊断设备基础信息；隐私较敏感字段放在完整上报里。

### A-07：SSE 连接状态必须可观测

在 Debug 或设置页显示：

- 当前 base URL。
- access token 是否存在，不显示 token 原文。
- SSE 状态：CONNECTING / CONNECTED / DISCONNECTED / ERROR。
- 最近一次连接错误。
- 最近一次设备上报结果。

这不是给普通用户看的功能，而是给联调和运维定位“为什么管理端看不到在线/设备”的诊断入口。

## 五、验收标准

### 5.1 在线状态验收

1. 清空 App 数据后登录。
2. 登录成功 3 秒内，Android 日志出现 `SSE connected: 200`。
3. 服务端日志出现：

```text
SSE notifications: connected user=<user_id> remote=<addr> role=<role>
```

4. 管理端 `SystemService/GetOnlineUsers` 返回 count >= 1，并包含该用户。
5. App 退后台后，服务端记录 disconnected；管理端在线数下降。
6. App 回前台后，SSE 自动重连；管理端在线数恢复。
7. access token 过期且 refresh 失败时，App 回登录页，SSE 断开。

### 5.2 设备信息验收

1. 登录请求的 `ClientInfo.device_id` 非空且稳定。
2. 同一设备重复登录不会生成重复设备记录，只更新 `updated_at`。
3. 登录后管理端设备列表至少显示：
   - `device_id`
   - `user_id`
   - `display_name/username/code_id`
   - `updated_at`
4. 设备详情上报成功后，管理端显示：
   - `os_type=android`
   - `brand/model`
   - `os_version`
   - `app_version/build_number`
5. 未授权详细采集时，不能影响基础设备记录和用户绑定。

## 六、测试要求

必须新增或更新以下测试：

- `SessionViewModelTest`
  - 登录成功后保存 token、设置 session、连接 SSE、触发设备上报。
  - session expired 后清 token、断 SSE、发出 RequireLogin。
  - foreground/background 调用 reconnect/disconnect。
- `AuthRepositoryTest`
  - LoginRequest/RegisterRequest 必须带 `ClientInfo.device_id` 和 `user_agent`。
  - 返回完整 `AuthSessionResult`。
- `DeviceRepositoryTest`
  - 无详细 consent 时仍能构造基础上报，或明确跳过但不破坏登录基础设备记录。
  - RPC 失败不影响登录流程，但错误可观测。
- `SseManagerBackoffTest`
  - 401 或无 token 不应进入无限快速重连。
  - 正常断线使用指数退避。

## 七、禁止事项

- 禁止登录成功后只设置 `ConnectTransportProvider.setToken()` 而不通知 `SessionViewModel`。
- 禁止在多个 ViewModel 中各自管理 SSE 连接。
- 禁止设备上报失败静默到完全不可观测。
- 禁止把 access token 打到日志。
- 禁止让详细设备采集 consent 阻断基础 `device_id` 上报。
- 禁止为了让管理端“看起来有数据”伪造设备或在线用户。
