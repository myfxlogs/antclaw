# 客户端设备上报实施指南

> 目标读者：客户端 AI Agent（Android / Web / 移动端）
> 关联改动：服务端已在 Login / Register 成功时自动将 `ClientInfo.device_id` 写入 `devices` 表
> 最后更新：2026-05-14

---

## 一、背景

服务端 `Login` RPC 已改造：客户端在 `LoginRequest.client`（`ClientInfo`）中填入 `device_id`，登录成功后设备记录会自动出现在管理后台「设备管理」页面。

**客户端只需做两件事：**
1. 生成一个稳定的 `device_id`
2. 在 `LoginRequest` 和 `RegisterRequest` 中填入 `ClientInfo`（含 `device_id`）

---

## 二、device_id 生成规则

`device_id` 字符串，长度 ≤ 255，建议不超过 64 字符。

### Android

```kotlin
import android.provider.Settings
import java.util.UUID

fun getDeviceId(context: Context): String {
    val androidId = Settings.Secure.getString(
        context.contentResolver, Settings.Secure.ANDROID_ID
    )
    // ANDROID_ID 在工厂重置后会变化，但稳定性足够作为设备标识
    return "android-${androidId.take(16)}"
}
```

### iOS

```swift
import UIKit

func getDeviceId() -> String {
    if let id = UIDevice.current.identifierForVendor?.uuidString {
        return "ios-\(id)"
    }
    // Fallback: 生成后存 Keychain，下次取回
    return Keychain.load("antclaw_device_id") ?? {
        let id = UUID().uuidString
        Keychain.save("antclaw_device_id", value: id)
        return "ios-\(id)"
    }()
}
```

### Web

```typescript
function getDeviceId(): string {
  const key = 'antclaw_device_id';
  let id = localStorage.getItem(key);
  if (!id) {
    id = `web-${crypto.randomUUID()}`;
    localStorage.setItem(key, id);
  }
  return id;
}
```

**核心原则**：device_id 一旦生成就持久化存储，同一设备多次登录用同一个 ID。

## 三、ClientInfo 字段填充

### proto 定义

```protobuf
message ClientInfo {
  string user_agent = 1;
  string ip_address = 2;
  string device_id  = 3;
}
```

### 各字段要求

| 字段 | 必填 | 说明 | 示例 |
|---|---|---|---|
| `device_id` | **是** | 按上述规则生成并持久化 | `"android-a1b2c3d4e5f6g7h8"` |
| `user_agent` | 建议 | `AppName/Version (OS; Model)` | `"AntClaw/1.0.0 (Android 14; Pixel 8)"` |
| `ip_address` | 建议填入 | 客户端公网 IP（如有），否则留空让服务端从请求头推断 | `""` 或 `"203.0.113.42"` |

## 四、代码示例

### Android (Kotlin + Connect-RPC)

```kotlin
// 在登录时
suspend fun login(email: String, password: String) {
    val clientInfo = clientInfo {
        deviceId = getDeviceId(context)
        userAgent = "AntClaw/${BuildConfig.VERSION_NAME} (Android ${Build.VERSION.SDK_INT}; ${Build.MODEL})"
        ipAddress = "" // 服务端会从 X-Forwarded-For 推断
    }
    val req = loginRequest {
        this.email = email
        this.password = password
        client = clientInfo
    }
    val resp = authClient.login(req)
    // token 等后续处理...
}
```

### iOS (Swift + Connect-Swift)

```swift
func login(email: String, password: String) async throws {
    var clientInfo = Antclaw_V1_ClientInfo()
    clientInfo.deviceID = getDeviceId()
    clientInfo.userAgent = "AntClaw/\(appVersion) (iOS \(UIDevice.current.systemVersion); \(deviceModel))"
    clientInfo.ipAddress = ""
    
    var req = Antclaw_V1_LoginRequest()
    req.email = email
    req.password = password
    req.client = clientInfo
    
    let resp = try await authClient.login(req)
    // ...
}
```

### Web / TypeScript

```typescript
import { createClient } from '@connectrpc/connect';
import { AuthService } from '@antclaw/proto/antclaw/v1/auth_pb';

async function login(email: string, password: string) {
  const req = {
    email,
    password,
    client: {
      deviceId: getDeviceId(),
      userAgent: navigator.userAgent,
      ipAddress: '',
    },
  };
  const resp = await authClient.login(req);
  // ...
}
```

### Register 同理

`RegisterRequest` 也包含 `ClientInfo client = 6;` 字段，**注册时也必须填入**。

## 六、后续可选项：上报完整设备信息

登录成功自动写入 `devices` 表后，设备记录只有 `device_id` + `user_id`，其他字段（model、brand、os_version 等）为空。

客户端可在登录后**异步**调用 `ReportDeviceInfo` RPC 补全详细信息：

```protobuf
rpc ReportDeviceInfo(ReportDeviceInfoRequest) returns (ReportDeviceInfoResponse);

message DeviceInfo {
  string device_id = 1;
  string model = 2;
  string brand = 3;
  string os_version = 4;
  string os_type = 5;     // "android" / "ios" / "web"
  string app_version = 6;
  string build_number = 7;
  int32 screen_width = 8;
  int32 screen_height = 9;
  string network_type = 10;
  string timezone = 11;
  string locale = 12;
  string manufacturer = 13;
  string fingerprint = 14;
  string user_id = 15;
  // display_name/username/code_id 由服务端 JOIN 填充，客户端不用填
}
```

**不是必须项**——基础设备标识已经通过登录自动写入，`ReportDeviceInfo` 只是锦上添花。

## 五、在线状态上报（必做）

管理后台「仪表盘」显示的"在线用户数"**不是登录就有**，而是统计活跃的 SSE 长连接数。

客户端登录成功后，**必须立即建立 SSE 连接**到 `/sse/notifications`：

```javascript
// 带上 JWT token
const token = loginResponse.accessToken;
const es = new EventSource("https://ad.alfq.org/sse/notifications", {
  // 浏览器原生 EventSource 不支持自定义 header，
  // 需要通过 Cookie 或 fetch + ReadableStream 实现带 Authorization 的 SSE
});

// Android / iOS 等原生客户端：用 OkHttp / URLSession 发起 GET，
// 手动加 Authorization: Bearer <token> header，然后流式读取
```

### 各端 SSE 实现要点

| 端 | 关键点 |
|---|---|
| Web | `EventSource` 不支持自定义 header。两种方案：(1) 服务端支持 Cookie 鉴权；(2) 用 `fetch()` + `ReadableStream` 模拟 SSE |
| Android | `OkHttp` GET 请求 + `Authorization: Bearer <token>` header，流式读取 `response.body.source()` |
| iOS | `URLSession` GET + header，`URLSessionDataDelegate` 逐块接收 |

**必须维持的长连接特性**：
- 连接断开自动重连（3s 间隔）
- 收到 `: ping` 心跳忽略
- 收到 `event: notification` 时解析 JSON payload 展示推送

**不连 SSE → 后台永远看不到在线状态。**

---

## 七、验收标准

1. 客户端登录后，管理后台 `https://<host>:8081/devices` 能看到该设备记录（至少有 `device_id` 和用户名）
2. 同一设备多次登录，`updated_at` 更新而不会产生重复记录
3. 客户端登录后 SSE 连接已建立，管理后台仪表盘"在线用户"能看到该用户
4. `device_id` 在应用卸载重装后可能变化（取决于实现策略），这是预期行为
