# 服务端项目设计缺陷整改落地指南

> 目标读者：Go 服务端 AI Agent  
> 适用范围：`backend/`、`proto/`、`scripts/`、`.github/`  
> 上游依据：`docs/项目设计缺陷与工程化审查报告.md`  
> 专项依据：`docs/服务端-在线状态与设备信息整改指南.md`  
> 不处理范围：Web 端、Admin 前端页面体验

---

## 一、整改目标

服务端当前主要问题不是功能数量不足，而是生产可信度不足。整改目标是把后端从“功能可调用”提升到“数据可信、错误明确、边界清晰、可测试、可持续扩展”。

本指南要求 AI Agent 按以下顺序落地：

```text
真实数据契约
  -> 认证与设备/在线链路
  -> 服务分层与组合根
  -> 统一错误模型
  -> 测试与 CI gate
```

禁止为了让客户端或管理端“看起来有数据”返回样例、合成、随机或静默 fallback 数据。

---

## 二、P0：真实数据契约整改

### S-P0-01：移除生产路径样例数据 fallback

**问题**

以下服务仍在生产路径返回样例或合成数据：

- `backend/internal/service/macro/service.go`
- `backend/internal/service/calendar/service.go`
- `backend/internal/service/user/service.go`

典型问题：

- FRED/MQL5 拉取失败后继续返回 sample data。
- `GetMe` 空 userID 时回退到 `user-1`。
- 内存 map 中预置 `demo@antclaw.io`。

**目标行为**

| 场景 | 返回 |
|---|---|
| 上游 API 未配置 | `connect.CodeFailedPrecondition` 或领域错误 `ErrProviderNotConfigured` |
| 上游 API 请求失败 | `connect.CodeUnavailable`，保留 cause |
| 数据库无数据 | `connect.CodeNotFound` 或 `ErrDataInsufficient` |
| 用户未登录/无 userID | `connect.CodeUnauthenticated` |
| 用户不存在 | `connect.CodeNotFound` |

**落地要求**

1. 新增领域错误包，建议路径：`backend/internal/service/apperror` 或 `backend/internal/domain/errors.go`。
2. 定义：

```go
var (
    ErrDataInsufficient    = errors.New("data insufficient")
    ErrProviderNotConfigured = errors.New("provider not configured")
    ErrUpstreamUnavailable = errors.New("upstream unavailable")
    ErrNotFound            = errors.New("not found")
    ErrPermissionDenied    = errors.New("permission denied")
)
```

3. Handler 层统一转换为 Connect error，禁止 service 直接拼 UI 文案。
4. 如果必须保留 demo 模式，只能由显式配置打开，例如 `ANTCLAW_DEMO_MODE=true`，并且响应字段必须标记 `data_quality=demo`；默认关闭。

**验收**

- `rg -n "sample data|fallback data|demo@|generate.*Data|getSample" backend/internal backend/cmd` 不应命中生产路径。
- 无凭据启动时 smoke 不应返回样例宏观/日历数据。

### S-P0-02：修复 UserService 内存态与默认用户

**问题**

`backend/internal/service/user/service.go` 使用内存 map，且空 userID 默认 `user-1`。

**目标**

`UserService` 必须走 PostgreSQL user store，不允许内存用户作为生产实现。

**落地要求**

1. 定义 `UserRepository` 接口，放在 service 或 infra 边界清晰的位置。
2. PostgreSQL 实现读取 `users`、membership、history、pins 等真实表。
3. `GetMe(ctx, userID)` 中 userID 为空直接返回 unauthenticated。
4. `SetAiKey` 不允许空实现返回 success；应接 BYOK 服务或返回 unimplemented。

**测试**

- userID 为空返回 Unauthenticated。
- user 不存在返回 NotFound。
- 正常用户返回 DB 中真实 displayName/codeId/roles。

## 三、P0：在线状态与设备信息整改

本部分按专项文档执行：`docs/服务端-在线状态与设备信息整改指南.md`。

必须优先修复：

1. `DeviceService/ReportDeviceInfo` 接入登录鉴权。
2. `ReportDeviceInfo` 不再信任客户端 `user_id`。
3. 修复 Android 不传 `user_id` 时覆盖 `devices.user_id=NULL` 的问题。
4. `presence.Tracker` 从 `map[userID]OnlineUser` 改为多连接模型。
5. `GetOnlineUsers` 补齐 `display_name/code_id`。
6. `ListDevices` 的 `total` 尊重过滤条件，并补权限边界。

**验收脚本建议**

新增：

```text
scripts/e2e/sc-31-device-presence.sh
```

覆盖：

```text
login with client.device_id
  -> report device info
  -> admin list devices sees bound user
  -> open /sse/notifications
  -> GetOnlineUsers sees user
  -> close SSE
  -> user disappears
```

## 四、P1：服务分层与组合根整改

### S-P1-01：拆分 `cmd/antclaw-api/main.go`

**问题**

`backend/cmd/antclaw-api/main.go` 同时负责配置、迁移、DB、Redis、密钥、凭据、service 初始化、handler 注册、SSE、HTTP server。

**目标结构**

建议新增：

```text
backend/internal/app/api/
├── config.go          # 从环境加载 API 运行配置
├── infra.go           # Postgres / Redis / crypto / resolver 初始化
├── services.go        # service graph
├── rpc.go             # Connect handler 注册
├── sse.go             # SSE handler 注册
└── app.go             # BuildHTTPHandler / Close
```

`cmd/antclaw-api/main.go` 只保留：

```go
func main() {
    app, err := api.New(...)
    if err != nil { log.Fatal(err) }
    defer app.Close()
    server := &http.Server{Addr: cfg.Addr, Handler: app.Handler()}
    runServerAndWaitSignal(server)
}
```

**约束**

- 不改变外部 API 行为。
- 不在拆分时顺手重构业务逻辑。
- 先搬迁结构，再做行为修改。

### S-P1-02：Handler 不直接承载业务规则

检查并整改所有 `backend/internal/adapter/rpc/*_handler.go`：

| 允许 | 禁止 |
|---|---|
| 参数读取、鉴权上下文读取、调用 service、Connect error 转换 | 直接 SQL、复杂分页、业务状态机、外部 API 调用 |

已经分层的模块保持；未分层模块按：

```text
adapter/rpc -> service -> infra/postgres / infra/apiclient
```

落地。

设备模块建议拆为：

```text
backend/internal/service/device/service.go
backend/internal/infra/postgres/device_repository.go
backend/internal/adapter/rpc/device_handler.go
```

## 五、P1：统一错误模型与客户端可恢复行为

### S-P1-03：定义服务端错误码矩阵

新增文档或 proto 注释，建议：`docs/服务端-错误码与客户端行为.md`。

最少覆盖：

| 领域错误 | Connect Code | Android 行为 |
|---|---|---|
| 未登录/Token 失效 | Unauthenticated | refresh，失败回登录 |
| 无权限 | PermissionDenied | 展示无权限，不重试 |
| 参数错误 | InvalidArgument | 标记输入错误 |
| 数据不足 | NotFound 或 FailedPrecondition | 显示空态/数据不足 |
| 上游不可用 | Unavailable | 显示可重试错误 |
| 内部错误 | Internal | 显示通用错误，记录日志 |

### S-P1-04：Handler 统一转换错误

建议新增 helper：

```go
func connectError(err error) error
```

禁止在每个 handler 内随意：

```go
connect.NewError(connect.CodeInternal, err)
```

导致数据不足、权限、参数问题全部变成 internal。

## 六、P1：测试补齐

### S-P1-05：每个 service 包至少一个测试

当前多个 `backend/internal/service/*` 包缺少 `_test.go`。按风险优先级补：

第一批：

- `user`
- `calendar`
- `macro`
- `notify`
- `presence`
- `datasource`
- `alerts`

第二批：

- `price`
- `vol`
- `sentiment`
- `strategy`
- `systemai`
- `report`

### S-P1-06：关键测试场景

必须覆盖：

- 无数据不返回样例数据。
- 上游失败返回明确错误。
- 用户为空不默认 demo user。
- 设备上报不覆盖 user_id。
- 同用户多 SSE 连接的在线统计。
- admin 接口非管理员返回 403。

## 七、P1：CI 与脚本整改

### S-P1-07：新增后端质量扫描

建议新增：

```text
scripts/ci/backend-quality-guard.sh
```

扫描：

```bash
rg -n "sample data|fallback data|demo@|getSample|generate.*Data|math/rand" backend/internal backend/cmd
rg -n "_, _ = .*\\.Exec|_, _ = .*\\.Query|catch|panic\\(" backend/internal backend/cmd
```

注意需要白名单，避免误伤测试与文档。

### S-P1-08：CI 必须执行

`.github/workflows/ci.yml` 保持并强化：

```bash
cd backend && go vet ./...
cd backend && go test ./...
bash backend/scripts/lint-protocol.sh
bash scripts/lint-filesize.sh
bash scripts/ci/backend-quality-guard.sh
```

不得使用 `|| true` 绕过后端质量检查。

## 八、推荐实施顺序

1. 修复设备上报鉴权和 `user_id` 覆盖。
2. 修复 presence 多连接模型。
3. 移除 macro/calendar/user 生产 fallback。
4. 增加统一领域错误和 Connect error 映射。
5. 拆分 `cmd/antclaw-api/main.go` 组合根。
6. 为 P0/P1 service 补测试。
7. 增加 CI guard。

## 九、最终验收

完成整改后必须通过：

```bash
cd backend && go vet ./...
cd backend && go test ./...
bash backend/scripts/lint-protocol.sh
bash scripts/lint-filesize.sh
API_BASE=http://localhost:8082 bash scripts/smoke-rpc.sh
bash scripts/e2e/run_all.sh
```

如果本轮只改了部分模块，至少运行对应包测试和相关 smoke/e2e，并在提交说明中列明未覆盖风险。
