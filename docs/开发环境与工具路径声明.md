# 开发环境与工具路径声明

> 目的：固定记录 AntClaw 项目在当前 Linux 环境中的关键工具路径、插件机制和依赖约束，避免后续出现“工具已安装但找不到路径”的问题。

## 1. 基础环境

- 操作系统：Linux（Ubuntu 系）
- Shell：`bash`
- 工作区：`/home/mluser/code/antclaw`

## 2. 关键可执行路径声明

### 2.1 Buf

- 已安装可执行文件路径：`/home/mluser/go/bin/buf`
- 已验证版本：`1.68.3`

建议在会话中显式注入（临时）：

```bash
export PATH="/home/mluser/go/bin:$PATH"
```

建议写入 `~/.bashrc`（永久）：

```bash
echo 'export PATH="/home/mluser/go/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

### 2.2 Go 相关路径

- `GOPATH`：`/home/mluser/go`
- `GOBIN`：空（使用默认 `GOPATH/bin`）

## 3. Buf 配置与插件机制（统一 V2）

### 3.1 配置文件

- 根配置：`buf.yaml`（`version: v2`）
- 生成配置：`buf.gen.yaml`（`version: v2`）

### 3.2 插件策略

当前使用 **远程插件**，不依赖本地 `protoc-gen-*` 可执行文件：

- `buf.build/protocolbuffers/go`
- `buf.build/connectrpc/go`
- `buf.build/bufbuild/es`

说明：

- 这套配置可避免本地缺 `protoc-gen-es` 导致 `buf generate` 失败。
- 如后续切回本地插件模式，必须额外安装对应 `protoc-gen-*` 并保证其在 `PATH` 中。

## 4. 依赖锁文件约束

- `buf.yaml` 升级为 V2 后，必须使用 V2 `buf.lock`。
- 若出现报错 `got a v1 buf.lock file for a v2 buf.yaml`，执行：

```bash
export PATH="/home/mluser/go/bin:$PATH"
buf dep update
```

## 5. 标准生成与验证命令

```bash
# 1) 确认 buf 可见
export PATH="/home/mluser/go/bin:$PATH"
command -v buf
buf --version

# 2) 更新依赖锁（必要时）
buf dep update

# 3) 生成代码
buf generate

# 4) 后端构建验证
cd backend && go build ./...
```

## 6. 故障排查清单

### 6.1 `buf: command not found`

1. 检查是否存在：`ls /home/mluser/go/bin/buf`
2. 检查 PATH：`echo "$PATH"`
3. 注入后重试：`export PATH="/home/mluser/go/bin:$PATH"`

### 6.2 `could not find protoc plugin for name es`

优先确认 `buf.gen.yaml` 是否为 V2 远程插件配置；若是远程插件仍报错，检查：

1. 网络可访问 Buf Registry；
2. `buf` 版本可用；
3. 依赖锁文件是否已更新（执行 `buf dep update`）。

### 6.3 `got a v1 buf.lock file for a v2 buf.yaml`

直接执行：

```bash
buf dep update
```

## 7. 维护要求

- 涉及工具路径、生成链路、插件策略变更时，必须同步更新本文件。
- 任何新增“本地插件依赖”必须明确记录其安装位置与 PATH 注入方式。
